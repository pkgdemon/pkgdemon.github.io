nextbsd-pkg: install-test CI

Never publish a package repo that can't install itself. Add a pre-publish gate to nextbsd-pkg that assembles the flat repo, then actually installs NextBSD-everything into a scratch root the same way the ISO builders do — failing on any file conflict or silently-dropped dependency before the repo is published. Plus a fast, deterministic cross-package file-ownership check at assembly time so the common case (two components owning one path) fails in seconds with an exact culprit. Directly closes nextbsd#370; the concrete invariant is that NextBSD-userland and NextBSD-freebsd-compat can never co-own a path.

Status: planning — scoping for review. Synthesised from a pipeline audit (2026-07-10) of nextbsd-pkg/scripts/{build,verify}.sh, nextbsd-freebsd-compat/scripts/strip-collisions.sh, and the two ISO builders (nextbsd/build.sh, gershwin-on-nextbsd/build.sh). Every path and line reference below is from a current checkout.

Motivating incident A shipped snapshot had NextBSD-freebsd-compat and NextBSD-userland both owning /usr/share/man/man3/syslog.3.gz. pkg(8)'s SAT solver resolved the hard file conflict by silently dropping NextBSD-userland — the package that carries /sbin/launchd. pkg install NextBSD-everything reported success; the rootfs came out with no init. It was caught only downstream, by gershwin-on-nextbsd's ISO-build guard [ -x $ROOTFS/sbin/launchd ]. nextbsd-pkg published it green because nextbsd-pkg never installs what it builds.

1. The gap: publish without installing

nextbsd-pkg/scripts/build.sh repackages each component's continuous artifact into one pkg(8) package and publishes a flat repo. It runs in a FreeBSD VM (vmactions/freebsd-vm@v1, 14.2), triggered by repository_dispatch: userland-updated, workflow_dispatch, or PR.

PackageSource (component continuous)Owns
NextBSD-freebsd-compatnextbsd-base-$ARCH.tar.gzwhole base rootfs
NextBSD-kernelnextbsd-kernel-$ARCH.tar.gzboot/kernel/kernel
NextBSD-kernel-extensions*kext*.tar.gz (amd64)kexts
NextBSD-userlandnextbsd-userland-$ARCH.tar.gzDarwin system layer
NextBSD-everything— (meta)nothing; depends on all four

The package plist is generated per component by find . \( -type f -o -type l \) over the extracted tarball (build.sh:41), then pkg create. Each package owns exactly whatever files are in its tarball. There is no cross-package arbitration at this layer — two components claiming the same path is created silently and only resolved (by dropping a package) at consumer install.

The existing gate is metadata-only There is a verify job — scripts/verify.sh — but it runs pkg install -n -y NextBSD-everything (verify.sh:36). The -n is a dry-run: it exercises the SAT solver on catalog metadata but never extracts a single file into a root. A two-owners-of-one-path collision manifests at extraction/registration, not in metadata — so the dry-run passes green while the real install would drop a package. That is precisely the hole.

2. Three reasons conflicts slip through

  1. Temporal skew from independent rolls (the primary cause). The only cross-repo collision check today is nextbsd-freebsd-compat/scripts/strip-collisions.sh, and it runs during the base build. It fetches the userland continuous tarball as of that moment (strip-collisions.sh:18, curl .../nextbsd-userland/releases/download/continuous/...), intersects the staged base against it (comm -12, line 30-33), and strips approved overlaps. But compat and userland publish on independent triggers — compat on toolchain-updated/PR, userland on its own commits. A base that passed its gate is later combined by nextbsd-pkg with a newer userland it never saw. That is exactly the syslog.3.gz path: userland #30 (083c720, "man: install man pages") started shipping it after the base last built its collision list.
  2. The assembler does no file-ownership check. build.sh generates each plist independently and never intersects the four staged trees before pkg create. Nothing at pkg-assembly time — the one place the actual combined snapshot exists — validates that the four packages partition the filesystem.
  3. The only pre-publish gate never extracts. verify.sh's pkg install -n means the collision-induced drop of NextBSD-userland//sbin/launchd passes CI green (see §1).

3. The invariant & ownership contract

Invariant: across NextBSD-{freebsd-compat, kernel, kernel-extensions, userland}, no two packages own the same path, and pkg install NextBSD-everything installs every dependency (drops none). "userland and compat never conflict," stated as a testable property.

Ownership contract (today it lives implicitly in compat/scripts/collisions; this plan makes it explicit and enforced): where the Darwin userland ships a functional equivalent of a FreeBSD-base file, userland owns the canonical copy and the base strips it. The recurring overlap classes:

ClassExampleOwner
Man pages that follow an overlay-owned daemon/libman3/syslog.3.gz, man8/syslogd.8userland (follows syslogd/asl)
Overlaid tools at a shared path/usr/sbin/syslogd (Apple ASL vs FreeBSD)userland
Shared libs / runtimelibBlocksRuntime.souserland (/usr/lib/system)
Headers/usr/include/Block*.huserland

Root fix for skew The install-test (Layer B) validates the combined snapshot, which is where skew becomes observable — but it is reactive. To make the ownership contract proactive, the deterministic Layer A check runs at pkg-assembly time against the actual base+userland being combined, not a point-in-time base-build intersection. That moves the collision gate to the one place that sees the real pair.

4. Two-layer defense

One gate is enough to close #370, but two are cheap and complementary:

Whenat assembly, before pkg createafter repo build, before publish
Howintersect the four staged plistspkg -r <root> install NextBSD-everything
Speedinstant (a sort/comm)one real extraction (~seconds)

Blind tonon-path shadowing, ABI/solver behaviornothing relevant — it is the real thing

Layer A gives a fast, precise "you added X, and Y already owns it" the moment someone introduces an overlap. Layer B is the authoritative backstop that proves the published repo actually installs. Ship both; Layer B is the one that satisfies #370's acceptance, Layer A is the one that makes the failure legible.

5. Layer A — cross-package ownership check

build.sh already stages each component into its own root and derives a plist. Before publishing, intersect them pairwise. Because compat is the big base and userland is the overlay, the load-bearing pair is compat×userland, but the check is general:

# after each component's stage dir + plist exist, before `pkg repo`
# collect "package: path" for every owned path, detect any path with >1 owner
: > /tmp/owners
for comp in freebsd-compat kernel kernel-extensions userland; do
    [ -d "stage/$comp" ] || continue
    ( cd "stage/$comp" && find . \( -type f -o -type l \) ) \
        | sed "s#^#$comp #" >> /tmp/owners
done
# any path owned by >1 package (2nd field), minus the approved contract list
awk '{ p=$1; $1=""; c[$0]++; owner[$0]=owner[$0]" "p } END {
        for (f in c) if (c[f] > 1) print f " <=" owner[f] }' /tmp/owners \
    | grep -vf scripts/allowed-shared.txt > /tmp/conflicts || true
if [ -s /tmp/conflicts ]; then
    echo "FATAL: components co-own paths (nextbsd#370):" >&2
    cat /tmp/conflicts >&2
    exit 1
fi

Notes: (1) this is the ownership contract expressed as code — scripts/allowed-shared.txt is the deliberate-shared allowlist (normally empty; the four packages should partition cleanly). (2) It supersedes the temporal-skew problem for the assembler because it runs on the actual base+userland pair being combined, unlike compat's point-in-time strip-collisions.sh. (3) It is arch-neutral and needs no VM — it can even run in the Linux prep step before the FreeBSD VM.

6. Layer B — real install-test (the #370 gate)

Mirror exactly what the ISO builders already do — a host-side pkg -r <root> install (no boot, no chroot), pointed at a private REPOS_DIR holding only the just-built flat repo, with the NextBSD ABI pin. Then assert the post-conditions that a bare exit code would miss.

# in the FreeBSD VM, after `pkg repo out/repo`
ROOT=$(mktemp -d)
repos=$(mktemp -d)
cat > "$repos/nextbsd.conf" <<EOF
nextbsd: { url: "file://$PWD/out/repo", enabled: yes, signature_type: none }
EOF
export ABI="FreeBSD:15:${ABIARCH}" IGNORE_OSVERSION=yes OSVERSION="$(uname -K)" ASSUME_ALWAYS_YES=yes

pkg -r "$ROOT" -o REPOS_DIR="$repos" update -f
pkg -r "$ROOT" -o REPOS_DIR="$repos" install -y NextBSD-everything   # NO -n: real extraction

# 1. the whole point: install must produce a working init
[ -x "$ROOT/sbin/launchd" ]  || { echo "FAIL: NextBSD-everything install produced no /sbin/launchd"; exit 1; }
[ -x "$ROOT/bin/launchctl" ] || { echo "FAIL: no /bin/launchctl"; exit 1; }

# 2. NO dependency silently dropped — the syslog bug was a *successful* install
#    that just excluded NextBSD-userland. Exit code alone would not catch it.
for p in NextBSD-freebsd-compat NextBSD-kernel NextBSD-userland; do
    pkg -r "$ROOT" -o REPOS_DIR="$repos" info -e "$p" \
        || { echo "FAIL: $p missing from NextBSD-everything install (SAT solver dropped it)"; exit 1; }
done
echo "OK: NextBSD-everything installs cleanly, all deps present, launchd present"

Why pkg info -e per dep is non-negotiable The failure mode was not a non-zero exit — it was a green pkg install that dropped NextBSD-userland to resolve the file conflict. Only checking each meta-dependency actually landed (info -e) catches "installed successfully, minus the important package." The launchd guard is the human-obvious proxy; the per-dep loop is the general form.

Arch: run per publishing arch. amd64 always; arm64 packages carry FreeBSD:15:aarch64 and install by extraction (no execution), so the same pkg -r works cross-arch on the x86 VM — same pattern verify.sh already relies on, but doing a real extraction instead of -n.

7. Implementation: the build.yml changes

  • Layer A — a step in scripts/build.sh (or a new scripts/check-ownership.sh it calls) right before pkg repo. Fails the packaging step with the exact culprit. No new job.
  • Layer B — replace verify.sh's install -n with the real pkg -r <root> install + assertions above. It already runs in the FreeBSD VM job, so it is an edit, not a new VM.
  • Gating — both must run on pull_request and before the publish step on the auto (userland-updated) path. A repo that can't install itself must fail before pkg repo is uploaded, whichever trigger fired.
  • Keep verify.sh's metadata dry-run too if desired — it is a cheap first cut — but it is no longer the last word.

8. Edge cases & what this does not catch

  • Non-path shadowing. Two libs at different paths where rtld search order makes one shadow the other (the libBlocksRuntime.so class the superseded header warns about) is not an exact-path tie — Layer A won't see it, and Layer B only catches it if it breaks the install. Out of scope here; still governed by the superseded list.
  • Runtime-only conflicts. Two packages whose files coexist fine but misbehave together at boot are a boot-test concern (that lives in the ISO/kernel CI), not a pkg-install concern.
  • Third-party repo interactions (#357) are separate — this gate validates the NextBSD set in isolation via a private REPOS_DIR, exactly as the ISO builders do (so the VM's own signed repos don't perturb the solver).
  • Deeper structural fix (optional, later): have nextbsd-pkg apply the ownership contract itself (run compat's strip logic against the actual userland being packaged) so overlaps are resolved at assembly, not just detected. Layer A detecting + failing is the safe first step; auto-stripping at assembly is a follow-up once the contract is trusted.

9. Cost, rollout, checklist

Cost: Layer A is a sort/comm (milliseconds). Layer B is one real pkg install extraction into a tmpdir (seconds) in a VM the job already spins up. Negligible.

Rollout:

  1. Land scripts/check-ownership.sh + scripts/allowed-shared.txt (empty) and wire it into build.sh before pkg repo. Layer A
  2. Rewrite verify.sh: private REPOS_DIR → real pkg -r install NextBSD-everything → launchd + bin/launchctl + per-dep info -e asserts. Layer B
  3. Ensure both gate the publish step on every trigger, not just PR.
  4. Backfill: run the new gate against the current published snapshot once, to confirm today's repo is clean (and to seed allowed-shared.txt only if a legitimately-shared path exists).

Acceptance (#370) nextbsd-pkg CI installs NextBSD-everything into a clean rootfs and fails the build on any file conflict or dropped dependency, before the repo is published — and the common userland×compat overlap fails in seconds at assembly with the exact path named.
