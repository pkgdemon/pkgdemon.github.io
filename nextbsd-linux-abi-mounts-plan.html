Linux ABI mounts

Who mounts /proc, /sys, /dev/fd and /dev/shm for Linux programs on NextBSD now that no /etc/fstab ships? The plan must also cover the case where the Linux root does not exist yet. The answer is a single boot-time LaunchDaemon that does what FreeBSD’s rc.d/linux does. It creates the Linux root’s mount points and always mounts them, whether or not a Linux userland has been installed.

2026-09-21. Three research agents read FreeBSD releng/15.0 (rc.d/linux, the Linuxulator, vfs_lookup.c, fdescfs, tmpfs), debootstrap 1.0.145 and the FreeBSD port’s patches, dpkg, Chromium’s shared-memory code, Apple launchd-258 through -842, and NextBSD’s launchd at main. Nothing here has been run on a NextBSD box yet; §7 lists the tests that would prove it. Planning only.

The short answers.

  1. Always mount the compat set, and pre-create it. A one-shot LaunchDaemon, org.nextbsd.linux, runs /usr/libexec/nextbsd-linux --compat at boot. It creates $emul/{proc,sys,dev} and mounts all five filesystems, where $emul is compat.linux.emul_path, default /compat/linux. It does this even when no Linux userland is installed. This is exactly stock FreeBSD’s behaviour with linux_enable=YES: rc.d/linux runs mkdir -p and mounts unconditionally (rc.d/linux:17-26, 74-80).
  2. debootstrap works with the mounts in place, with one step afterwards. debootstrap does not require an empty target. It stacks its own devfs, fdescfs and linprocfs during stage 2 and removes them on exit. The catch is that it first unmounts our $emul/proc, so the wrapper re-runs nextbsd-linux --compat when debootstrap finishes (§3).
  3. No trigger is needed. Because the mounts always exist, a root that appears later (debootstrap, an untarred image, linux_base) is already mounted. The apt wrapper still re-runs the tool after bootstrapping. launchctl start org.nextbsd.linux is the manual re-run. WatchPaths is inert on this launchd, but restoring it is optional (§5).
  4. The native set is optional, not required. An empty but mounted /compat/linux gives every Linux process Linux-style /proc, /sys, /dev/fd and /dev/shm through the alt-root lookup. That includes static AppImage runtimes with no Linux userland at all. Mounting linprocfs on the real /proc is safe for native binaries but not needed (§4).

1. How the Linuxulator finds Linux paths

  • Alt root per exec. On every Linux-ABI exec, linux_pwd_onexec() resolves compat.linux.emul_path and installs it as the process’s alt root. If the path does not exist, execution continues with no alt root (sys/compat/linux/linux_util.c:77-94). emul_path is one global CTLFLAG_RWTUN string, default /compat/linux (:71-75).
  • ENOENT falls back. namei() tries every absolute path under the alt root first. Only when the whole lookup fails with ENOENT does it restart from the real root (sys/kern/vfs_lookup.c:741-757, and :689-697 for the fast path). EACCES and ENOTDIR do not fall back, and neither does a create whose parent exists.
  • Inside a chroot there is no alt root. pwd_chroot sets the alt root to the new root (kern_descrip.c:4206-4208), so a chroot into the Linux root only needs the mounts inside it.

So with an empty but mounted $emul, /proc/*, /sys/* and /dev/* resolve to the compat instances, and every other path (/lib64/ld-linux…, /etc/passwd, /tmp/.mount_*) returns ENOENT under $emul and is retried on the real root. That is today’s behaviour with no alt root, plus one negative lookup.

A likely correction to #54. #54 records that AppImages “need the native set”. The mechanism says otherwise. The probable explanation is that in those tests /compat/linux/proc existed as an unmounted empty directory created by linux_base-rl9. /proc/self was then ENOENT under $emul and fell back to the native /proc, which only worked once linprocfs was mounted there. Test T3 settles it.

Mount order (§8 has the full spec):

  1. linprocfs on $emul/proc
  2. linsysfs on $emul/sys
  3. devfs on $emul/dev
  4. fdescfs -o linrdlnk on $emul/dev/fd. linrdlnk is required, because Bun and claude-code resolve cwd through readlink("/dev/fd/N") (#54).
  5. tmpfs mode=1777,size=… on $emul/dev/shm

devfs goes first, and no mkdir is needed for dev/fd or dev/shm: devfs supplies fd, and linux_dev_shm_create() puts shm/ in every devfs instance at ABI init (sys/compat/linux/linux.c:699-709). The tool also re-asserts kern.elf64.fallback_brand=3 only if it reads -1. The kernel default is already 3 (patch 0009). It never touches elf32.

Where the root comes from. The root is sysctl -n compat.linux.emul_path. To move it persistently, write the line unquoted in /etc/sysctl.conf, as compat.linux.emul_path=/compat/debian. launchctl bootstrap applies that file before load -D all (launchctl.c:2342). sysctl does not strip quotes, so a quoted value would include them. --root PATH overrides for one run, and the wrapper uses it before the sysctl is set.

Pi 5. The linsysfs boot panic mentioned in #171 is fixed (nextbsd-kernel#209, patches 0056/0057). It happened at init time and was unrelated to mounting. nextbsd-kernel#212, where the RP1 PCI subtree is missing from /sys, is still open.

3. debootstrap into a mounted root

This was the deciding question. Here is what debootstrap does, with our five mounts already in place:

Workaround: after debootstrap exits, whether it succeeded or failed, the wrapper runs nextbsd-linux --compat, which remounts only proc. No pre-unmount is needed. The tool keeps a --pristine fallback that unmounts first and remounts after, which is the Handbook’s exact order. It is there in case some maintainer script misbehaves because linsysfs is visible at $TARGET/sys during bootstrap. Stock FreeBSD never has linsysfs mounted there during bootstrap.

Bootstrap in place. Do not bootstrap into a temporary directory and rename it into place: the root carries mounts, so it cannot be replaced by a rename. Bootstrapping in place is what makes B1 work.

4. The native set

  • No base or Darwin program reads /proc expecting FreeBSD procfs. grep '"/proc' over ps, procstat, libkvm, libprocstat, truss and libc/gen in releng/15.0 finds nothing. In the Darwin userland, the only readers are under TARGET_OS_LINUX (CFPlatform.c:181-184, CFBundle_Internal.h:441-444). GNUstep uses libkvm on FreeBSD (NSProcessInfo.m:528-602).
  • /dev/fd with fdescfs linrdlnk only changes getattr and readdir to report symlinks (fdesc_vnops.c:459-472, 583-588). open("/dev/fd/N") still dups, and descriptors above 2 appear, as on macOS.
  • Visible changes: ls /proc looks like Linux, and /dev/fd/N shows as symlinks.
  • /sys may be a dangling symlink to usr/src/sys from FreeBSD’s distribution target. The tool must replace it rather than fail on mkdir.

Decision: ship it as --native, controlled by native_mounts= in the config and off by default. Under B1, Linux processes don’t need it. Turn it on only if /dev/fd/N parity for native shells is wanted.

5. Triggering, and restoring WatchPaths

  • Boot: org.nextbsd.linux with RunAtLoad and no KeepAlive. load -D all dispatches it after mount -vat nonfs and the /tmp and /var/run sweep, so admin fstab lines show as already. Optionally add StartOnMount, which is implemented in this launchd (core.c:2489, 4009, 7204). It re-runs the job on any mount, and the tool is idempotent.
  • After creating a root: the apt/debootstrap wrapper runs the tool directly. The manual re-run is launchctl start org.nextbsd.linux (ipc.c:406-410). There is no kickstart in the launchd-842 CLI.
  • WatchPaths, QueueDirectories and KeepAlive.PathState are inert. launchctl rewrites them into com.apple.fsevents.matching LaunchEvents (launchctl.c:1611-1648). No EventMonitor job exists, and libxpc’s publisher API is stubbed (libxpc/xpc/private.h:60-68). The getty plist records that PathState is not implemented (org.nextbsd.getty.ttyv0.plist:64-68).
  • Restoring them is optional, and is its own ticket. Apple’s last native implementation is launchd-392.39 (launchd_core_logic.c: semaphoreitem_watch 5135-5223, semaphoreitem_callback 5226-5291, PATH_* reasons 305-320). It watches the parent directory until the target appears, and falls back to a 3 s poll on ENOTSUP. The backport is about 350–450 lines in core.c, plus removing distill_fsevents(). On FreeBSD, open the watch fds with O_PATH, because O_EVTONLY is shimmed to 0 and would pin the vnode (open(2) allows EVFILT_VNODE on O_PATH). Three things want it: nextbsd#278 “Lever D”, userland#54 option B, and the getty PathState guard. An EventMonitor daemon instead would need XPC plumbing NextBSD has deferred.
  • Rejected: autofs (not in the kernel), a pkg trigger as the primary mechanism (the root comes from debootstrap, not pkg), and a kernel “first Linux exec” event (none exists in sys/compat/linux).

6. /dev/shm sizing

  • Linux: tmpfs defaults to 50% of RAM (Documentation/filesystems/tmpfs.rst:78-92).
  • FreeBSD: tmpfs is unlimited unless size= is given, with vfs.tmpfs.memory_percent at 95% as a global guard. NextBSD has no swap, and the live /cow is an uncapped tmpfs (#326, #329).
  • Chrome: it uses memfd_create first, and the Linuxulator implements it (linux_file.c:1757). It falls back to /dev/shm and aborts if /dev/shm is unwritable (platform_shared_memory_region_posix.cc:300-345). How much Chrome writes there on NextBSD is unmeasured.

Policy. size is a percentage of hw.physmem, page-rounded, with a 128 MiB floor:

  • 50% on installed systems, for Linux parity.
  • 25% on live media, detected by / being unionfs.

It can be overridden with shm_size= in the config. With the native set on, mount one tmpfs and nullfs it to /dev/shm, so there is a single cap. A cap turns an OOM kill (#326) into ENOSPC inside the offending Linux process.

8. Tool spec: /usr/libexec/nextbsd-linux

/bin/sh, idempotent, and safe to run at every boot and at any time later. The whole run takes lockf -k -t 60 /var/run/nextbsd-linux.lock.

Actions: --compat (default), --native, --all, --unmount [--native|--all] [--force], --status [--json] and --check. --root PATH overrides emul_path for one run.

Config is /etc/nextbsd-linux.conf:

  • native_mounts=NO
  • shm_size=50%|25%|<bytes>
  • shm_share=YES
  • chroot_nullfs="" (e.g. /home)
  • fallback_brand=YES

For each mount, in §2’s order:

  1. If the path is missing, mkdir -p it (only for proc, sys, dev and the native /proc and /sys). On failure, E_MKDIR.
  2. If statfs shows the right filesystem already mounted: already.
  3. If a different filesystem is mounted there: E_CONFLICT. Don’t stack; continue with the rest.
  4. Otherwise mount -t fs -o nocover,…. If that returns EBUSY, re-check with statfs: a concurrent run means already, anything else is E_CONFLICT.
State--compat
$emul absent, parent writablecreate {proc,sys,dev}, mount five, exit 0
$emul absent, parent read-only or path invalidexit 2 (an error, not a silent no-op)

Exit codes:

  • 0: ok or no-op
  • 1: usage
  • 2: mkdir failed or the root is invalid
  • 3: conflict
  • 4: mount refused (message verbatim)
  • 5: busy on unmount
  • 6: lock timeout

With several errors the highest code wins, and every path is still attempted. --unmount goes in reverse order, never uses -f unless --force, and never removes directories.
