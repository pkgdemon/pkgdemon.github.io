NextBSD CI Pipeline Plan

Automated FreeBSD kernel cross-build pipeline using GitHub Actions free-tier runners. No self-hosted runners, no open firewall ports, no paid plans required.

1. Architecture Overview

nextbsd-redux/freebsd-src (fork, auto-synced daily) | | changed? no --> stop | changed? yes --> repository_dispatch v nextbsd-redux/kernel-builder (toolchain containers) | | publishes ghcr.io/nextbsd-redux/kernel-builder:{amd64,aarch64}-latest | --> repository_dispatch v nextbsd-redux/nextbsd-kernel (kernel + patches + config) | | builds kernel (NO_MODULES), uploads artifact | --> repository_dispatch v nextbsd-redux/nextbsd-modules (module builds, layered on kernel obj) | | builds modules, uploads artifact v release artifacts (tar.gz on GitHub Releases)

2. Repos

RepoPurposeTriggers
freebsd-srcGitHub fork of freebsd/freebsd-src, all branchesScheduled daily sync
kernel-builderDockerfile + workflow to build cross-compilation toolchain containers for amd64 and aarch64repository_dispatch from freebsd-src sync, or manual
nextbsd-kernelKernel patches (patches/), custom kernel config (config/NEXTBSD), build workflowrepository_dispatch from kernel-builder, push to patches/** or config/**, or manual
nextbsd-modulesModule build workflow, consumes kernel obj artifactrepository_dispatch from nextbsd-kernel

3. Design Decisions

3.1 Why releng/15.0?

  • Userland packages from pkg are built against 15.0-RELEASE ABI
  • Custom kernel stays ABI-compatible — pkg install works for everything in userland
  • Stable branch, fewer surprise breakages in patches
  • make buildworld / make buildkernel is self-hosting by design — the host OS version doesn't matter, the build bootstraps its own toolchain from the source tree

3.2 Why Linux runners for cross-building?

  • Docker support — macOS runners cannot run Docker
  • Docker layer caching — toolchain layer cached, only rebuild when upstream changes
  • 20 concurrent jobs on free plan (vs 5 for macOS)
  • 1x cost multiplier if ever moving to paid (macOS is 10x)
  • FreeBSD's own CI cross-builds on Ubuntu runners — proven path

3.3 Why kernel modules must be built (not from pkg)?

Kernel modules are linked against the exact kernel config and source they're built with. A custom kernel (even with small patches like increasing the Mach syscall limit) means stock kmod packages won't load reliably. Modules must be built from the same patched source.

3.4 Why separate repos instead of one monorepo?

  • Each repo has a single responsibility and independent trigger conditions
  • Toolchain rebuild (~15 min) doesn't block kernel builds that only changed patches
  • Module builds only run when kernel obj actually changes
  • Clean separation of concerns: infrastructure (kernel-builder) vs. code (nextbsd-kernel) vs. artifacts (nextbsd-modules)

4. Repo: kernel-builder

4.1 Dockerfile

FROM ubuntu:24.04

ARG TARGET=amd64
ARG TARGET_ARCH=amd64
ARG FREEBSD_BRANCH=releng/15.0

RUN apt-get update && apt-get install -y \
    clang-18 lld-18 bmake git libarchive-tools \
    && rm -rf /var/lib/apt/lists/*

RUN git clone --depth 1 --branch ${FREEBSD_BRANCH} \
    --filter=blob:none --sparse \
    https://github.com/freebsd/freebsd-src.git /usr/src \
    && cd /usr/src \
    && git sparse-checkout set sys

RUN cd /usr/src && make -j$(nproc) kernel-toolchain \
    TARGET=${TARGET} TARGET_ARCH=${TARGET_ARCH}

4.2 Workflow: .github/workflows/build-toolchain.yml

name: Build Toolchain Containers
on:
  repository_dispatch:
    types: [upstream-updated]
  workflow_dispatch:
  schedule:
    - cron: '0 6 * * 1'  # weekly fallback

env:
  REGISTRY: ghcr.io
  FREEBSD_BRANCH: releng/15.0

jobs:
  build:
    runs-on: ubuntu-24.04
    strategy:
      matrix:
        include:
          - target: amd64
            target_arch: amd64
          - target: arm64
            target_arch: aarch64
    permissions:
      packages: write

    steps:
      - uses: actions/checkout@v4

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          context: .
          file: Dockerfile.${{ matrix.target }}
          push: true
          build-args: |
            TARGET=${{ matrix.target }}
            TARGET_ARCH=${{ matrix.target_arch }}
            FREEBSD_BRANCH=${{ env.FREEBSD_BRANCH }}
          tags: |
            ${{ env.REGISTRY }}/nextbsd-redux/kernel-builder:${{ matrix.target }}-latest
            ${{ env.REGISTRY }}/nextbsd-redux/kernel-builder:${{ matrix.target }}-${{ github.sha }}

      - name: Trigger downstream kernel build
        run: |
          gh api repos/nextbsd-redux/nextbsd-kernel/dispatches \
            -f event_type=toolchain-updated \
            -f "client_payload[sha]=${{ github.sha }}" \
            -f "client_payload[target]=${{ matrix.target }}"
        env:
          GH_TOKEN: ${{ secrets.DISPATCH_TOKEN }}

5. Repo: freebsd-src (fork sync)

5.1 Workflow: .github/workflows/sync-fork.yml

name: Sync Fork
on:
  schedule:
    - cron: '0 6 * * *'  # daily 6am UTC
  workflow_dispatch:

jobs:
  sync:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
        with:
          ref: releng/15.0
          fetch-depth: 1

      - name: Get current SHA
        id: before
        run: echo "sha=$(git rev-parse HEAD)" >> $GITHUB_OUTPUT

      - name: Sync from upstream
        run: gh repo sync ${{ github.repository }} --branch releng/15.0
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}

      - name: Check if changed
        id: after
        run: |
          git fetch origin releng/15.0
          NEW_SHA=$(git rev-parse origin/releng/15.0)
          echo "sha=$NEW_SHA" >> $GITHUB_OUTPUT
          if [ "${{ steps.before.outputs.sha }}" != "$NEW_SHA" ]; then
            echo "changed=true" >> $GITHUB_OUTPUT
          else
            echo "changed=false" >> $GITHUB_OUTPUT
          fi

      - name: Trigger toolchain rebuild
        if: steps.after.outputs.changed == 'true'
        run: |
          gh api repos/nextbsd-redux/kernel-builder/dispatches \
            -f event_type=upstream-updated \
            -f "client_payload[sha]=${{ steps.after.outputs.sha }}" \
            -f "client_payload[branch]=releng/15.0"
        env:
          GH_TOKEN: ${{ secrets.DISPATCH_TOKEN }}

6. Repo: nextbsd-kernel

6.1 Directory structure

nextbsd-kernel/
  patches/
    0001-increase-mach-syscall-limit.patch
    series                # ordered list of patches to apply
  config/
    NEXTBSD               # custom kernel configuration
  .github/
    workflows/
      build.yml

6.2 Patch maintenance

Patches are plain git format-patch diffs, applied in the order listed in patches/series. To create a new patch:

# Make changes in a local FreeBSD checkout
cd /usr/src
# ... edit files ...
git format-patch -1 -o /path/to/nextbsd-kernel/patches/
# Add to series file
echo "0002-my-change.patch" >> /path/to/nextbsd-kernel/patches/series
# Push -- CI runs automatically

6.3 Workflow: .github/workflows/build.yml

name: Build NextBSD Kernel
on:
  repository_dispatch:
    types: [toolchain-updated]
  push:
    paths: ['patches/**', 'config/**']
  workflow_dispatch:

env:
  TARGET: amd64
  TARGET_ARCH: amd64
  FREEBSD_BRANCH: releng/15.0

jobs:
  kernel:
    runs-on: ubuntu-24.04
    container:
      image: ghcr.io/nextbsd-redux/kernel-builder:amd64-latest
    steps:
      - uses: actions/checkout@v4

      - name: Apply patches
        run: |
          cd /usr/src
          for p in $(cat $GITHUB_WORKSPACE/patches/series); do
            git apply $GITHUB_WORKSPACE/patches/$p
          done

      - name: Copy kernel config
        run: cp $GITHUB_WORKSPACE/config/NEXTBSD /usr/src/sys/amd64/conf/

      - name: Build kernel (no modules)
        run: |
          cd /usr/src
          make -j$(nproc) buildkernel \
            TARGET=${{ env.TARGET }} \
            TARGET_ARCH=${{ env.TARGET_ARCH }} \
            KERNCONF=NEXTBSD \
            NO_MODULES=yes

      - name: Upload kernel artifact
        uses: actions/upload-artifact@v4
        with:
          name: nextbsd-kernel-amd64
          path: /usr/obj/**/sys/NEXTBSD/

      - name: Upload obj tree for modules
        uses: actions/upload-artifact@v4
        with:
          name: kernel-obj-amd64
          path: /usr/obj/
          compression-level: 6

      - name: Trigger module build
        run: |
          gh api repos/nextbsd-redux/nextbsd-modules/dispatches \
            -f event_type=kernel-updated \
            -f "client_payload[sha]=${{ github.sha }}" \
            -f "client_payload[run_id]=${{ github.run_id }}"
        env:
          GH_TOKEN: ${{ secrets.DISPATCH_TOKEN }}

7. Repo: nextbsd-modules

7.1 Workflow: .github/workflows/build.yml

name: Build NextBSD Modules
on:
  repository_dispatch:
    types: [kernel-updated]
  workflow_dispatch:

env:
  TARGET: amd64
  TARGET_ARCH: amd64
  FREEBSD_BRANCH: releng/15.0

jobs:
  modules:
    runs-on: ubuntu-24.04
    container:
      image: ghcr.io/nextbsd-redux/kernel-builder:amd64-latest
    steps:
      - name: Download kernel obj tree
        uses: actions/download-artifact@v4
        with:
          name: kernel-obj-amd64
          path: /usr/obj/
          run-id: ${{ github.event.client_payload.run_id }}
          github-token: ${{ secrets.DISPATCH_TOKEN }}

      - name: Apply patches to source
        run: |
          cd /usr/src
          # Re-apply patches (source tree in container is unpatched)
          # Patches fetched from nextbsd-kernel repo
          git clone --depth 1 https://github.com/nextbsd-redux/nextbsd-kernel.git /tmp/nk
          for p in $(cat /tmp/nk/patches/series); do
            git apply /tmp/nk/patches/$p
          done
          cp /tmp/nk/config/NEXTBSD /usr/src/sys/amd64/conf/

      - name: Build modules
        run: |
          cd /usr/src
          make -j$(nproc) buildkernel \
            TARGET=${{ env.TARGET }} \
            TARGET_ARCH=${{ env.TARGET_ARCH }} \
            KERNCONF=NEXTBSD \
            NO_KERNEL=yes

      - name: Upload modules artifact
        uses: actions/upload-artifact@v4
        with:
          name: nextbsd-modules-amd64
          path: /usr/obj/**/modules/

      - name: Create release
        if: github.event.client_payload.release == 'true'
        run: |
          cd /usr/obj
          tar czf /tmp/nextbsd-modules-amd64.tar.gz ./*/modules/
          gh release create "v$(date +%Y%m%d)-modules" \
            /tmp/nextbsd-modules-amd64.tar.gz \
            --repo nextbsd-redux/nextbsd-modules \
            --title "NextBSD Modules $(date +%Y-%m-%d)" \
            --notes "Built against FreeBSD ${{ env.FREEBSD_BRANCH }}"
        env:
          GH_TOKEN: ${{ secrets.DISPATCH_TOKEN }}

8. Estimated Build Times

StageFirst runCached run
Fork sync + change detection~1 min~1 min
Toolchain container build~15 minskipped (no upstream change)
Kernel build (no modules)~15-20 min~15-20 min
Module build (layered)~15-20 min~15-20 min
Total wall-clock (typical patch push)~17-22 min to kernel artifact

When upstream hasn't changed and no patches are pushed, nothing runs. Zero wasted minutes.

9. Setup Checklist

  1. Fork freebsd/freebsd-src into nextbsd-redux/freebsd-src (all branches)
  2. Create nextbsd-redux/kernel-builder with Dockerfiles + workflow
  3. Create nextbsd-redux/nextbsd-kernel with patches, config, workflow
  4. Create nextbsd-redux/nextbsd-modules with workflow
  5. Create a fine-grained Personal Access Token with repo scope for cross-repo repository_dispatch
  6. Add the token as DISPATCH_TOKEN secret in all four repos
  7. Run kernel-builder workflow manually to bootstrap the first toolchain container
  8. Add initial patches and kernel config to nextbsd-kernel, push to trigger first build

11. Future Enhancements

  • ccache in toolchain container — incremental kernel rebuilds could drop to 5-10 min when patches touch few files
  • Parallel module builds — fan out individual modules into separate jobs, each pulling the kernel obj artifact
  • aarch64 kernel builds — same pipeline, just reference the aarch64-latest container
  • libc builds — if Mach syscall patches require libc shims, add a nextbsd-libc repo consuming a world-builder container (~3-5 min build)
  • Selective module builds — use path filters to detect which module source changed and only rebuild affected modules
  • Weekly upstream validation — scheduled workflow that tests all patches against current upstream, alerts on breakage
