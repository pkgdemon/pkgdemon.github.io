FreeBSD configd — porting plan

A FreeBSD-only port of Apple's configd — the network/system-configuration daemon — that drops Mach IPC, replaces it with GNUstep Distributed Objects (DO), uses libdispatch for all kernel/file/process events, and integrates as a launchd-supervised service. Owns the canonical state of every network interface, hostname, and DNS resolver setting on the system. Companion to the freebsd-launchd port.

Status: planning v0

  • Repo: github.com/pkgdemon/freebsd-launchd — monorepo. configd source lives under configd/ at the top of the launchd repo, alongside src/ (launchd) and (eventually) kmodloader/. Single build pipeline, single CI, single boot test gates everything.
  • Mission: replace FreeBSD's network configuration plumbing — /etc/rc.d/netif, /etc/rc.d/dhclient, /etc/rc.d/wpa_supplicant, /etc/rc.d/hostname, /etc/rc.d/routing, /etc/resolv.conf management — with one launchd-supervised netconfigd daemon backed by a single canonical plist (/Local/Library/Preferences/Network.plist).
  • Source: Apple configd-963.270.3 (latest tag at apple-oss-distributions/configd, Apache 2.0). 289 source files. Phase 1 amputation drops the Mach-only files; what remains needs FreeBSD-shaped rewrites for the IPC + event-loop + DHCP layers.
  • No Mach IPC, no libxpc, no IOKit, no AirPort/CoreWLAN. All Mach/IOKit paths in the imported source are deleted; service-to-service IPC uses GNUstep Distributed Objects (NSConnection + NSPortCoder over AF_UNIX) instead of Mach ports + XPC.
  • Event loop: libdispatch dispatch sources only. DISPATCH_SOURCE_TYPE_READ on PF_ROUTE for kernel iface events (replacing Darwin's PF_SYSTEM/KEV_NETWORK_CLASS); DISPATCH_SOURCE_TYPE_VNODE for live config-file reload; DISPATCH_SOURCE_TYPE_PROC for managed dhclient/wpa_supplicant child supervision; DISPATCH_SOURCE_TYPE_SIGNAL for shutdown/reload.
  • Plist parsing: GNUstep NSPropertyListSerialization (already linked into launchd; no additional libraries).
  • DHCP / IPv6 RA / WiFi: spawn FreeBSD's existing dhclient, rtsold, wpa_supplicant as NSTask children (Phase 1). Do not reimplement these protocols inside the daemon initially. Apple's configd absorbed DHCP into IPConfiguration after years of evolution; we earn that path the same way — only when there's a measurable reason.
  • Single source of truth: /Local/Library/Preferences/Network.plist — the canonical config the daemon reads and the GUI edits. Live-reloaded via WatchPaths-equivalent libdispatch vnode source. No /etc/rc.conf parsing, no /etc/hostname, no /etc/resolv.conf as user-edited file (the daemon writes resolv.conf from the plist).
  • Live ISO behavior: if no Network.plist exists, netconfigd auto-DHCPs every plugged ethernet interface and starts rtsold for IPv6 RA — matching the user's preferred rc.conf network_interfaces="auto" ifconfig_DEFAULT="DHCP" preset, without needing a config file.
  • Licensing: BSD-2-Clause top-level (matches the launchd repo and FreeBSD ecosystem). Apple configd source files retain their Apache 2.0 headers per-file. NOTICE enumerates Apple, GNUstep, and us.

1. Goal & non-goals

1.1 Goal

Port Apple's configd to FreeBSD as a launchd-supervised daemon (netconfigd), implementing the full Apple-style "one daemon owns network/system state" architecture: a single source-of-truth plist, kernel-event-driven reactivity, a Distributed Objects API the GUI uses to query/edit state, and supervised subprocesses (dhclient/rtsold/wpa_supplicant) for the protocols that already have working FreeBSD implementations. End state: a FreeBSD live ISO that boots with launchd as PID 1, netconfigd auto-configures every plugged interface (IPv4 DHCP + IPv6 RA), the user has a working network in seconds, and a future GUI tool can present/edit per-interface settings via a clean ObjC API.

1.2 Non-goals (this iteration)

  • No AirPort / CoreWLAN. WiFi authentication is delegated to wpa_supplicant, the FreeBSD-native tool. The plugin AirPort.framework stays out of tree.
  • No IOKit. Apple's InterfaceNamer uses IOKit to assign persistent names from USB/PCI metadata; we let the FreeBSD kernel name interfaces and don't try to override.
  • No Mach IPC. Same rule as the launchd port: every mach/... include, every .defs file, every bootstrap_port reference is amputated. NSConnection over AF_UNIX is the IPC.
  • No XPC. XPC services are not in tree. DO covers the same use cases for our scale.
  • No SimulatorSupport. The whole iOS/iPadOS-sim plugin is dropped.
  • No QoSMarking. Apple-specific framework, not portable.
  • No internal DHCP client (Phase 1). dhclient stays a subprocess. Phase 6+ may revisit.
  • No captive-portal detection. Apple's URL-probe heuristic is out of scope; users handle this through the browser.
  • No /etc/rc.conf compatibility layer. Network.plist is the only config file the daemon reads.

2. Repository

2.1 Monorepo: configd lives inside freebsd-launchd

One repo (github.com/pkgdemon/freebsd-launchd) holds launchd, configd, and any related tooling that follows. Reasons:

  1. Single build pipeline. build.sh, the chroot, the CI workflow, the boot test — all one. No second clone loop, no second CI surface, no version-skew between repos.
  2. Cross-component refactors are atomic. When the DO interface used by configd's scutil-port changes shape, both ends move in one commit. With separate repos, you'd have two PRs, two reviews, and a window where the system is broken.
  3. Discoverability. A new contributor clones one repo and sees the whole system. The pieces are obviously related; their separation across repos would be the artificial thing.
  4. Tooling parity with launchd's pattern. The launchd source already lives in src/ with Apple's odd nested structure (src/src/); adding configd/ and kmodloader/ as siblings is a natural extension.

2.3 How build.sh handles configd

No host-clone change — configd's source is already in the working tree. The chroot-side rsync that already brings src/ in just brings configd/ with it (via rsync -a $ROOT/{src,configd}/...). After make-launchd.sh finishes installing /sbin/launchd, build.sh calls make-configd.sh in the same chroot session, which compiles configd against the just-installed Foundation/libdispatch and installs /usr/libexec/netconfigd + /usr/sbin/scutil. Net additions to build.sh:

  • Extend the chroot rsync line: rsync -a "$ROOT/src/" "$WORK/rootfs/tmp/launchd/src/" → also stages configd/.
  • Append after the make-launchd.sh invocation: chroot "$WORK/rootfs" /tmp/launchd/make-configd.sh.
  • Add overlay file /Local/Library/Preferences/Network.plist (empty) so the daemon's auto-DHCP path fires on first boot.

Existing src/ location not renamed in this plan to avoid churn against the ongoing Phase 3+ launchd work. A future cosmetic commit can move src/ → launchd/ for parity once everything has stabilized; both plans (configd, kmodloader) tolerate either layout.

3. Architecture

One long-running daemon (netconfigd) owns all network and system-configuration state. It is launchd-supervised (KeepAlive=true), reacts to kernel events (PF_ROUTE), reacts to file changes (Network.plist via libdispatch vnode source), supervises subprocesses (dhclient, rtsold, wpa_supplicant via libdispatch proc sources), and exposes a Distributed Objects API on a known AF_UNIX socket so other processes (scutil, GUI tools, application reachability code) can query and modify state.

+----------------------------+ | /Local/Library/Preferences| | /Network.plist | +-------------+--------------+ | (vnode source: WRITE|EXTEND|DELETE) v +--------------------+ +----+-----+ +-------------------------+ | PF_ROUTE socket |---->|netconfigd|<----| /var/run/netconfigd.sock| | (RTM_NEWADDR/etc) | | (ObjC, | | (DO root: NetConfig- | +--------------------+ | GNUstep)| | Service @protocol) | +----+-----+ +-----------+-------------+ | | +-------------+--------------+ | scutil(1) / | NSTask children | | GUI tooling | - dhclient -b -n <iface> | v | - rtsold -a | +-------+-------+ | - wpa_supplicant -i ... | | NSConnection | | (proc source per child) | | client proxy | +----------------------------+ +---------------+ | v +----------+----------+ | kernel network stack| | (ifaddrs, routes, | | resolv.conf, ...) | +---------------------+

3.1 The dynamic store, GNUstep-flavored

Apple's configd publishes state to the SystemConfiguration "dynamic store" — a key-value space (keys like State:/Network/Interface/en0/IPv4) that processes subscribe to. We keep the same key naming for compatibility-of-mental-model, but back it with an NSMutableDictionary protected by a serial dispatch queue. Subscribers register interest via the DO connection; NSDistributedNotificationCenter-style fan-out notifies them when a subscribed key changes.

3.2 Interface state machine

Each NIC the daemon manages has an NCInterface object whose state machine is:

StateEntered viaActive subprocess
Downiface attached, no link, or admin-downnone
LinkUpRTM_IFINFO link activenone yet
DHCPv4config method=DHCP, link activedhclient -b -n <iface>
StaticV4config method=Static, link activenone (SIOCSIFADDR ioctls)
WPAWiFi method=WPA, link associatingwpa_supplicant -i <iface> -c <file>
Upv4 acquired (DHCP lease or static applied)(possibly dhclient still alive in background)

IPv6 is orthogonal: the daemon enables accept_rtadv via SIOCSIFADDR on every interface that reaches LinkUp, and ensures rtsold -a is running globally.

8. Dependencies

No new pkglist or buildpkgs entries beyond what freebsd-launchd already pulls in. The system domain (libdispatch + libobjc2 + tools-make + libs-base + libs-corebase) is already installed by the time configd builds. Configd needs:

  • Build-time: clang, lld (FreeBSD base); the gnustep-make framework already installed; pkgconf; the system-domain headers/libraries at /System/Library/.
  • Runtime: libdispatch.so, libgnustep-base.so, libgnustep-corebase.so, libobjc.so, libBlocksRuntime.so (all from system domain). Plus FreeBSD-base subprocesses: /sbin/dhclient, /usr/sbin/rtsold, /usr/sbin/wpa_supplicant (the last needs pkg install wpa_supplicant if not in base — verify).

The make-configd.sh dependency check: the script hard-checks /System/Library/Libraries/libgnustep-base.so + libdispatch.so (same pattern as make-launchd.sh). If they're missing, exit early with a clear error pointing to the system-domain build.

9. launchd integration

9.1 The plist

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key>
    <string>org.freebsd.netconfigd</string>
    <key>ProgramArguments</key>
    <array>
        <string>/usr/libexec/netconfigd</string>
    </array>
    <key>RunAtLoad</key>     <true/>
    <key>KeepAlive</key>     <true/>
    <key>Sockets</key>       <dict>
        <key>Listeners</key> <dict>
            <key>SockPathName</key> <string>/var/run/netconfigd.sock</string>
            <key>SockType</key>     <string>stream</string>
            <key>SockPathMode</key> <integer>438</integer> <!-- 0666 -->
        </dict>
    </dict>
</dict>
</plist>

launchd opens the AF_UNIX listener at boot and hands the fd to netconfigd via the standard launch_activate_socket protocol (or our equivalent in the FreeBSD launchd port). Until netconfigd is up, queued connections from scutil/GUI tools sit in the kernel's socket queue.

9.2 Boot ordering

netconfigd needs /System/Library/ populated (the GNUstep libs it links against). At boot:

  1. launchd starts as PID 1.
  2. launchd scans /System/Library/LaunchDaemons/, finds org.freebsd.netconfigd.plist.
  3. launchd opens /var/run/netconfigd.sock (the Sockets listener) and forks netconfigd with the fd in LISTEN_FDS environment.
  4. netconfigd reads its socket from the env, wraps it in NSSocketPort, creates an NSConnection with self as root.
  5. netconfigd reads /Local/Library/Preferences/Network.plist; if absent or empty, falls into the auto-DHCP path for every link-up ethernet iface.
  6. netconfigd installs PF_ROUTE source, vnode source, signal sources; calls dispatch_main().

The org.freebsd.network.auto.plist + helper script we sketched in the launchd-plan amendment becomes obsolete once netconfigd ships — netconfigd absorbs that role natively.

10. Network.plist schema

One canonical configuration file. Every per-host setting has a path here. The GUI tooling reads/writes this file directly (or talks to netconfigd over DO, which writes it back).

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
                       "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Hostname</key>
    <string>my-host</string>

    <key>Interfaces</key>
    <dict>
        <key>em0</key>
        <dict>
            <key>Method</key> <string>DHCP</string>
        </dict>

        <key>em1</key>
        <dict>
            <key>Method</key> <string>Static</string>
            <key>IPv4</key>
            <dict>
                <key>Address</key> <string>192.168.1.10/24</string>
                <key>Router</key>  <string>192.168.1.1</string>
            </dict>
        </dict>

        <key>wlan0</key>
        <dict>
            <key>Method</key> <string>WPA</string>
            <key>WPA</key>
            <dict>
                <key>ConfigFile</key> <string>/etc/wpa_supplicant.conf</string>
            </dict>
            <key>IPv4</key>
            <dict>
                <key>Method</key> <string>DHCP</string>
            </dict>
        </dict>
    </dict>

    <key>IPv6</key>
    <dict>
        <key>Mode</key> <string>Auto</string> <!-- Auto | Manual | Off -->
    </dict>

    <key>DNS</key>
    <dict>
        <!-- Optional. If absent, DNS is taken from DHCP. -->
        <key>Servers</key>
        <array>
            <string>1.1.1.1</string>
            <string>1.0.0.1</string>
        </array>
        <key>Search</key>
        <array>
            <string>example.com</string>
        </array>
    </dict>
</dict>
</plist>

Empty / absent Network.plist → the daemon auto-DHCPs every link-up ethernet, enables IPv6 RA via rtsold -a, leaves hostname as kernel default ("Amnesiac"), and lets DNS come from DHCP. This is the live-ISO default behavior; users get networking for free.

Per-iface dict missing → the iface defaults to DHCP if it's an ethernet that's link-up, untouched if it's anything else. A user who wants em0 to NOT auto-DHCP adds {"Method": "Disabled"}.

10.1 Schema versioning

Add a top-level "Version" key (integer) once we have post-v1 schema changes. v1 is implicit; v2+ ships the daemon's accepted version range.

11. scutil CLI tool

Apple's scutil is the "system configuration shell" — interactive and one-shot commands to query and edit the dynamic store. We port it as a DO client of netconfigd. Initial command set:

  • scutil --show — dump the entire dynamic store
  • scutil --get Hostname / --set Hostname my-host — single-key edits
  • scutil --interfaces — list managed interfaces with current state
  • scutil --reload — force netconfigd to re-read Network.plist
  • scutil --watch <key> — long-running, prints on store changes

The interactive Mach-shell mode of Apple's scutil is dropped (it depended on Mach store semantics). One-shot mode covers what users actually use.

  • Follow-up amputation commit per §6.1 (Mach + IOKit + AirPort + sim out).

  • Top-level Makefile + make-configd.sh.
  • main.m + NCDaemon — reads Network.plist (or auto-everything if absent), forks dhclient -b -n <iface> for each link-up ethernet iface, exec's rtsold -a for IPv6 RA. dispatch_main() loop with no event sources yet.

  • NCConfigWatcher: vnode source on Network.plist; diffs and reapplies on change.
  • Hot-plug: plug a new ethernet, daemon DHCPs it without reboot.

Phase 3 — DO server + scutil port

  • NetConfigService protocol; netconfigd registers self as DO root over launchd-handed AF_UNIX socket.
  • NCStore dynamic-store-equivalent with KVO-style notifications over DO.
  • Port scutil.tproj as a DO client; scutil --show / --get / --set / --watch work.
  • Boot test: ssh in, run scutil --interfaces, verify it returns the expected dictionary.

Phase 4 — IPv6 RA, hostname, DNS

  • IPv6 mode handling: Auto enables accept_rtadv per iface and runs rtsold -a; Manual applies static v6 from plist; Off disables.
  • Hostname key: daemon calls sethostname(3) on startup and on key change.
  • DNS key: daemon writes /etc/resolv.conf from the plist (with a "managed by netconfigd" header comment); falls back to DHCP-supplied DNS when key is absent.

Phase 5 — WiFi via wpa_supplicant

  • NCInterface WPA state branch: spawn wpa_supplicant -i <iface> -c <file> as managed child.
  • Watch wpa_supplicant's control-socket for ASSOCIATED / DISCONNECTED events; gate DHCP behind ASSOCIATED.
  • Schema sketch for inline credentials (Phase 6+) vs always-pointing-at-/etc/wpa_supplicant.conf.

Phase 6 — SCNetworkReachability for apps

  • Port the public reachability API. Apps call SCNetworkReachabilityCreateWithName(...) via the linked framework; under the hood it's a DO call to netconfigd.
  • This is what makes the GUI tooling actually pleasant — apps can subscribe to "reachability of github.com changed" and the GUI/daemon plumbing handles it.

Phase 7+ — optional, demand-driven

  • Internal DHCP client (drop the dhclient subprocess) — only if dhclient's behavior or footprint becomes a concern.
  • Captive-portal probing — when someone needs it.
  • Multiple-DNS-policy support (per-domain resolvers, etc.) — when someone needs it.

14. Open questions

Q1. Repo layout. — SETTLED. Monorepo: configd lives under configd/ at the top of freebsd-launchd. Reasons in §2.1: single build pipeline, atomic cross-component refactors, single CI surface, easier discoverability.
Q2. gdomap or direct NSSocketPort. Decision: direct NSSocketPort at /var/run/netconfigd.sock; no gdomap. Avoids running a name-registration daemon for one well-known service. If we end up with multiple DO services that need lookup, revisit.
Q3. Daemon binary path: /usr/libexec vs /sbin. Decision: /usr/libexec/netconfigd. Users don't invoke this directly; they invoke scutil at /usr/sbin/scutil. libexec is the FreeBSD hier(7) location for indirect-only daemons (/usr/libexec/getty, /usr/libexec/sendmail, etc.).
Q4. WiFi credentials storage: Network.plist or /etc/wpa_supplicant.conf? Phase 5 starts with the plist pointing at /etc/wpa_supplicant.conf — wpa_supplicant's existing config format is well-tested. Inline credentials in Network.plist (with the daemon writing wpa_supplicant.conf from them) is Phase 6+. Decision deferrable.
Q5. Replacing dhclient with internal DHCP. Open. Apple's path was years of IPConfiguration work; we shouldn't go there until there's a measurable reason (lease-renewal latency, footprint, etc.). Phase 7+ at earliest.
Q6. /etc/resolv.conf ownership. Daemon writes it from Network.plist's DNS key on Phase 4. Manual edits clobber on next boot. If users need a "don't manage resolv.conf" escape hatch, add a top-level "DNS": {"Mode": "Manual"} key. Decision deferrable.
Q7. Schema versioning gate. v1 is implicit. Add the "Version" key when v2 ships (or earlier if a GUI tool needs to know which schema it's reading). Cheap to add later.
Q8. Reachability API in Phase 6 — public framework or DO-only? Open. Public framework matches Apple's surface but adds linker-soname-stability concerns. DO-only is simpler. Settle when apps actually need it.
