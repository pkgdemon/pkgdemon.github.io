nextbsd-freebsd-world — a subtractive buildworld base

Replace nextbsd-freebsd-compat's additive curation (a 600-line srclist.txt that names every /usr/src dir to build, and springs a leak every time the build hits a tool nobody remembered to list) with a subtractive one: run a full buildworld, then remove the tiny, known set of paths the Apple/Darwin userland already owns. Ship the result as one package, NextBSD-world, and swap it in for NextBSD-freebsd-compat in NextBSD-everything once it's proven.

Status: planning — for review. Collision surface measured empirically against the live NextBSD-userland package (565 files) on thinkpad-t460s. Nothing built yet. New repo: nextbsd-redux/nextbsd-freebsd-world.

Why now In one evening the curated base needed three emergency PRs — #43 (locale data), #44 (diff/diff3/m4/patch/install/top/ncurses), #45 (gzip) — each discovered by a gershwin make install dying on a missing base tool. srclist.txt already carries 20+ comments of the form "replaces FreeBSD-openssl", "was shipped by FreeBSD-clibs-dev", "these are pkgbase FreeBSD-utilities". We are hand-reimplementing pkgbase, from memory, incompletely. That is the whack-a-mole, and it does not converge.

1. The thesis: subtract, don't add

The curated model's entire justification was "don't pull FreeBSD wholesale, because it collides with the Apple/Darwin userland." We measured that collision. It is three files (§2). The premise is false, and everything the model costs — the leak-prone srclist.txt, the per-dir dependency archaeology, the 3-PRs-a-night — is paid for a benefit that isn't there.

Flip the polarity:

 Additive (today: nextbsd-freebsd-compat)Subtractive (proposed: nextbsd-freebsd-world)
DefaultNothing. Every dir must be named in srclist.txt.Everything. Full buildworld.
Failure modeMissing a tool → runtime error, discovered by whoever hits it.Over-including a colliding file → caught at package time by the guard (§5).
MaintenanceChase every gap forever. Never converges.Maintain a short, explicit strip-list. Converges.
Dep correctnessEach dir's libs must already be curated in, by hand.buildworld builds every dep in order. Free.
Cost~20 min CI, but incomplete.~30–60 min CI, complete.

Subtractive curation converges because the thing being maintained — the strip-list — is bounded by what Apple ships, and Apple ships almost nothing in the userland path space.

2. The collision surface is ~3 files (measured)

pkg info -l NextBSD-userland on thinkpad-t460s: 565 files, distributed as:

CountPathWhat it is
389/usr/includeApple framework headers (IOKit, CoreFoundation, mach/…)
65/usr/lib/usr/lib/system/lib{CoreFoundation,IOKit,SystemConfiguration,dns_sd,launch,notify,xpc,system_kernel,system_asl}.so + debug — its own namespace
16/usr/sbinApple daemons: configd, mDNSResponder, notifyd, syslogd, diskarbitrationd, hostnamed, ipconfigd, kext{load,stat,unload,deps}, ioreg, bootstrap_server…
3/usr/binmig, cpdup, syslog
2/sbin, /binlaunchd, launchctl
—rest/usr/tests (51), /usr/share (16), /usr/libexec (5), /private/etc (6)

Zero general userland utilities. Verified by pkg which: sh, ls, cp, cat, ps, id, su, sshd, sed, diff, make are all NextBSD-freebsd-compat today. The Apple layer is frameworks + Mach daemons, living in namespaces (/usr/lib/system, the Mach-daemon names, Apple's /usr/include frameworks) that a FreeBSD buildworld never writes to.

Intersecting a stock installworld file list with those 565 paths yields the actual collision set:

strip /usr/sbin/syslogd

Both build it. Apple's ASL syslogd wins; drop FreeBSD's.

strip BlocksRuntime

libBlocksRuntime.*, Block.h, Block_private.h. Apple's /usr/lib/system is canonical (the existing no-clobber-apple-libs rule).

policy init / /etc

Not file clashes. launchd is PID 1 (different path from /sbin/init); /etc is owned by nextbsd-overlays, and we never run make distribution, so world never writes /etc.

That's the whole surface. Not a design problem — a three-line strip-list plus two policies we already enforce.

3. The nextbsd-freebsd-world repo

3.1 Naming

The new repo builds the FreeBSD-derived half of the OS; nextbsd-userland is the Apple/Darwin-derived half. The trap in the obvious name nextbsd-world: a FreeBSD world is itself mostly userland, so nextbsd-world vs nextbsd-userland reads as two names for the same layer. Distinguish by origin, not layer:

CandidateReads asNotes
rec nextbsd-freebsd-worldThe FreeBSD buildworld, successor to nextbsd-freebsd-compatKeeps the nextbsd-freebsd-* prefix, so the compat→world swap is self-evident. Explicit about both origin and method. Slightly long.
nextbsd-baseThe base system (FreeBSD's own term for buildworld)Shortest, and matches the existing artifact name nextbsd-base-*.tar.gz. Risk: “base” can read as the whole-OS base (kernel + userland), not specifically the FreeBSD world.
nextbsd-freebsdThe FreeBSD half, mirroring nextbsd-userlandCleanest origin-symmetry (FreeBSD half ↔ Darwin half). Con: says nothing about it being a full buildworld artifact.
no nextbsd-worldThe buildworldTechnically precise but semantically collides with nextbsd-userland (world ⊂ userland). Rejected.

Recommendation: repo nextbsd-freebsd-world (continuity + explicitness). Package name is a separate choice — existing convention is repo==pkg (nextbsd-freebsd-compat → NextBSD-freebsd-compat), which argues for NextBSD-freebsd-world; but since users type it in pkg install, the shorter NextBSD-world is defensible. This doc uses NextBSD-world as the package; flip if you prefer strict repo/pkg parity.

3.2 Layout

A sibling of nextbsd-kernel / nextbsd-kernel-modules, publishing one continuous artifact per arch that nextbsd-pkg repackages as the single NextBSD-world package.

nextbsd-freebsd-world/
  .github/workflows/build.yml   # buildworld -> installworld DESTDIR -> strip -> tar
  strip.list                    # explicit paths world must NOT own (Apple/overlay-owned)
  world.conf                    # WORLD_FLAGS knobs (WITHOUT_TOOLCHAIN, ...)
  scripts/
    strip-collisions.sh         # apply strip.list + assert against NextBSD-userland plist
  README.md

Source of truth for /usr/src is the same NextBSD fork of freebsd-src (releng/15.0-p9 + NextBSD patches) that nextbsd-freebsd-compat cross-builds today — so world's libc is bit-identical to what's shipping now, just complete.

4. Build: buildworld → strip → one package

  1. Build the world, keep ports as the compiler. WITHOUT_TOOLCHAIN=yes (we compile with ports llvm19, per the compat toolchain decision), plus the current lean knobs: 
    make -j${CPUS} buildworld \
  WITHOUT_TOOLCHAIN=yes WITHOUT_TESTS=yes WITHOUT_LIB32=yes
    Candidate size knobs for v2 (defer): WITHOUT_KERBEROS, WITHOUT_ZFS, WITHOUT_BLUETOOTH, WITHOUT_HAST, WITHOUT_INETD, WITHOUT_NIS, WITHOUT_BSNMP, WITHOUT_FTP, WITHOUT_TELNET, WITHOUT_SENDMAIL, WITHOUT_PPP, WITHOUT_BHYVE, WITHOUT_GAMES.
  2. Install the world, not the distribution. 
    make installworld DESTDIR=/stage WITHOUT_TOOLCHAIN=yes ...
# NB: NO `make distribution` — that is what would populate /etc + /var.
# Skipping it is how world stays out of the overlay's territory.
  3. Strip two lists (§4.1) plus the belt-and-suspenders dirs the base must never own: 
    rm -rf /stage/etc /stage/var /stage/root         # nextbsd/overlays own these
scripts/strip-collisions.sh  /stage collisions   # auto-derived + guard-enforced (§5)
scripts/strip-superseded.sh  /stage superseded    # explicit; each entry existence-asserted
  4. Tar the stage into nextbsd-freebsd-world-${ARCH}.tar.gz, publish to the repo's rolling continuous release — exactly the mechanism nextbsd-freebsd-compat uses today, so nextbsd-pkg needs only a source swap.

4.1 Two strip buckets: collisions vs superseded

Keep these distinct — they rot differently, so they're policed differently.

Bucket A — collisions must A path NextBSD-userland also owns; shipping both makes pkg refuse the install. Auto-derived by intersecting plists and guard-enforced (§5) — nobody maintains this by hand.

PathWinner (why)
/usr/sbin/syslogdApple ASL syslogd (userland)
libBlocksRuntime.*, Block.h, Block_private.hApple /usr/lib/system (the no-clobber-apple-libs rule)

Bucket B — superseded policy Not a collision — a distinct FreeBSD filename NextBSD keeps out because it has replaced the function with its own mechanism. Short, stable, and each line carries its replacement. Applied with an existence assertion: if a listed path isn't in the world (FreeBSD renamed/moved it), the build fails rather than silently no-op — so this list can't rot silently either.

StripSuperseded byFlag
/sbin/initlaunchd as PID 1 (userland) 
kldload, kldstat, kldunload, kldconfig, kldxrefkext{load,stat,unload} + kextd (userland / nextbsd-kernel-modules)R7 confirm the boot module-load path is kextd, not loader kld_list/loader.conf
devd, devmatchIOKit + configd/hwregd (userland)R7 confirm nothing in boot expects devd for auto-attach
bsdconfig, bsdinstallnextbsd-installer (/usr/sbin, userland) 
freebsd-updatepkg — base updates roll via NextBSD-* packages 

R7 — verify before stripping the kld/devd tools These are superseded only if the kernel's boot-time module loading and device attach truly go through the Apple/IOKit stack (kextd) and never fall back to base kldload/devd. On a partially-converted kernel that could brick module loading at boot. Cheap check on thinkpad-t460s: grep -r kld /boot/loader.conf /etc/rc.conf* 2>/dev/null and confirm kextd owns attach. Until confirmed, keep these in a superseded.candidate holding list, not the active one.

5. The self-policing collision guard

The one thing that must never rot is the strip-list. So don't trust it — verify it every build. strip-collisions.sh downloads the current NextBSD-userland plist, intersects it with the staged world's file list, and:

  • strips every path in that intersection (userland always wins);
  • fails the build if the intersection contains anything not enumerated in strip.list.
# pseudo
world_files=$(cd /stage && find . | sed 's/^\.//' | sort)
apple_files=$(fetch_userland_plist | sort)
overlap=$(comm -12 <(echo "$world_files") <(echo "$apple_files"))
unexpected=$(comm -23 <(echo "$overlap") <(sort strip.list))
[ -n "$unexpected" ] && { echo "NEW collision(s) — refuse to ship:"; echo "$unexpected"; exit 1; }
echo "$overlap" | while read f; do rm -f "/stage$f"; done

Payoff A future FreeBSD import or a new Apple daemon that starts owning a shared path can no longer silently clobber — it stops the build until someone decides who wins and records it. The maintenance burden becomes a git-blame-able one-line strip-list, not an open-ended hunt. This is the exact inverse of the current failure mode.

6. The nextbsd-pkg delta

nextbsd-pkg already assembles per-arch packages from component continuous artifacts. Changes:

  • Add a NextBSD-world package built from nextbsd-freebsd-world's artifact (same pkg create path as NextBSD-freebsd-compat).
  • During transition, build both NextBSD-freebsd-compat and NextBSD-world; only the NextBSD-everything meta decides which is live.
  • NextBSD-world is a strict superset of NextBSD-freebsd-compat's file set (minus the 3 stripped collisions, which userland provides anyway), so it can replaces:/conflicts: the compat package for a clean pkg upgrade.

7. Swap sequence & rollback

  1. P1 Stand up nextbsd-freebsd-world; get a green buildworld + guard pass on both arches. Publish continuous. (compat untouched)
  2. P2 nextbsd-pkg builds NextBSD-world alongside compat. Nothing consumes it yet.
  3. P3 Prove it: on a scratch box, pkg install NextBSD-world NextBSD-userland NextBSD-kernel, then run gershwin make install end-to-end. Assert NextBSD-world ⊇ compat (diff the two plists; every compat path present bar the intended strips).
  4. Cutover Flip one line in the NextBSD-everything meta: dep NextBSD-freebsd-compat → NextBSD-world. Ship. Bake.
  5. Retire After a bake window: drop compat from the meta, archive nextbsd-freebsd-compat, retire srclist.txt and its 3-PRs-a-night.

Rollback The cutover is a single meta dependency. If world regresses, revert that line and pkg upgrade falls back to compat — which stays built and published until the archive step. Zero-drama reversal at every stage before P5.

8. Risks & open flags

#RiskHandling
R1libc / /usr/lib/system overlap. World ships /lib/libc.so.7 etc.; userland ships /usr/lib/system/*. Must confirm no shared path (esp. any libdispatch/BlocksRuntime route).The guard (§5) is exactly this check, run every build. Pre-flight: run the intersection once by hand before P1 to seed strip.list.
R2/etc & overlays interplay. World must own no /etc; nextbsd-overlays owns it.Skip make distribution + rm -rf /stage/etc. Coordinate with the in-flight overlays split.
R3rc / service framework. compat added service(8)+rcorder for ports-pkg compat; a full world includes the rc framework. Confirm launchd-as-PID1 coexists (it does today) and decide whether ports' rc.d scripts stay inert-but-present.Default: keep the rc framework tools (ports expect them), never run FreeBSD init. Flag for boot-team confirm.
R4Build cost. Full world > curated subset.WITHOUT_TOOLCHAIN already skips the LLVM build (the expensive part). ~30–60 min/arch is acceptable for a base that changes rarely. v2 size knobs optional.
R5Package bloat. One big package pulls in subsystems we don't want (zfs, kerberos, …).Harmless at v1 (unused daemons don't run). Trim with WITHOUT_* in v2 if size matters. Not a correctness issue.
R6One package vs pkgbase split. We lose granular -dev/-lib packaging.Intentional: NextBSD is a substrate, not a granular distro. If granularity is ever wanted, make packages PKG_NAME_PREFIX=NextBSD is a drop-in v2 on the same buildworld.
