The nextbsd-overlays split

Today's nextbsd-userland/overlay/ is a mixed bag — user-editable /etc config and NextBSD-maintained daemon plists, all raw-copied into the package as plain files. That makes pkg upgrade clobber the user's config. Sort every overlay file by a single question — does pkg own it? — into three homes: a new nextbsd-overlays repo (assembler-laid, pkg-free), a proper install rule under src/ (built + packaged), or dropped.

Status: planning — for review. Two-agent sweep complete: full overlay inventory + packaging-clobber trace + src/ install mapping. Decisions D1–D5 resolved; two doctrine flags below. Nothing built yet.

Why master.passwd, sshd_config, and every pam.d/* ship as plain regular files owned by NextBSD-userland (nextbsd-pkg's mkpkg plist is a bare find, scripts/build.sh:41 — no @config). So pkg upgrade overwrites them with no .pkgnew: added users, tightened SSH, real PAM stacks — silently lost.

1. The axis: does pkg own it?

One question sorts every file and dissolves the confusing catch-all:

A pkg-free

User-editable config + the live-ISO layer. The image assembler lays these down; pkg must never touch them. → nextbsd-overlays.

B pkg-owned

Files NextBSD maintains and updates on upgrade (daemon plists, the ssh wrapper). Get a real install rule and ship in the package. → src/.

C neither

Files that shouldn't exist under NextBSD doctrine (rc.d glue) or duplicate the base. → dropped.

The overlay/ dir itself is then dissolved. (The nextbsd repo's own overlays/ and src/ are already gone from the #359 pkg refactor — only three stale build.sh comments remain, fixed in the seed step.)

2. Home A — the nextbsd-overlays repo

Organized by target, so each is a clean cp -R <subdir>/. <dest>/ that copies only content — no README/LICENSE/seed.sh splat:

nextbsd-overlays/
  rootfs/                       # -> cp -R rootfs/. $RF/       (image root; pkg-free)
    private/etc/
      master.passwd  group  login.conf  nsswitch.conf  fstab
      hosts  ttys  profile  shells  ld-elf.so.conf  gettytab  asl.conf
      ssh/sshd_config
      pam.d/{system,login,su,passwd,cron,sudo,other,sshd}
    boot/loader.conf.d/nextbsd.conf
  iso/                          # -> cp -R iso/. $ISOROOT/     (live-ISO layer)
    the /init pivot script + live loader.conf now inlined in nextbsd/build.sh
  seed.sh                       # only-if-absent variant, for a future first-boot path
  README.md  LICENSE  VERSION   # meta — sit OUTSIDE the subdirs, never copied

History is preserved: create the repo with git filter-repo keeping only these paths from nextbsd-userland and renaming overlay/ → rootfs/, so every file keeps its authorship and commits. The iso/ content lifts out of build.sh heredocs.

3. Home B — proper install under src/

nextbsd-userland/src/ is FreeBSD bsd.*.mk. Extra files install via bsd.files.mk (FILESGROUPS/FILESDIR), already pulled in by bsd.prog.mk — precedent at src/libmach/Makefile:80. The daemon plists move next to their daemon; a component's existing install step then drops the plist too (no build-driver change). Base-owned bits get one new files-only Makefile.

4. Home C — dropped (doctrine)

Resolved during build The agent flagged rc.d/ldconfig + rc.subr as doctrine violations to drop — but they turned out to be load-bearing and kept:

  • rc.d/ldconfig is an on-demand service(8) shim, NOT a boot job — FreeBSD-ports pkg post-installs hardcode service ldconfig restart, and the boot test's SERVICE-LDCONFIG gate (run.sh:977, exit 1) requires it. It does not violate the "no ldconfig boot job" rule. Kept, package-owned.
  • rc.subr is needed by service(8) / the shim above. Kept, package-owned.
  • services · protocols · man.conf — left package-owned as-is (no new base conflict introduced by the strip; revisit only if de-duping base later).

Net: the strip removes only the 22 user-config files; the maintained layer (incl. these) stays in the package.

5. Mechanism: strip · install · seed

Strip — get user /etc out of the package

Stop cp -aR overlay/. /stage/ (build-arch.yml:111) from folding the config in — simplest is to delete those files from overlay/ (they've moved to nextbsd-overlays). The find-plist then no longer lists them, so pkg can't own or clobber them.

Install — maintained files via make

The FILESGROUP rules put the plists/wrapper into $DESTDIR during each component's make install; the same find-plist now tracks them. pkg owns and updates them on upgrade — correct, because they're NextBSD's.

Seed — lay the pkg-free content at assembly time

# nextbsd/build.sh, after: $PKG install -y NextBSD-everything   (build.sh:97)
OVL="$WORK/nextbsd-overlays"
git clone --depth 1 https://github.com/nextbsd-redux/nextbsd-overlays "$OVL"
cp -R "$OVL/rootfs/." "$RF/"           # user /etc + loader fragment — un-owned by pkg
chmod 0600 "$RF/private/etc/master.passwd"
# ... existing pwd_mkdb / cap_mkdb (:137) then picks up the seeded master.passwd
# and the live-ISO assembler consumes "$OVL/iso/." into $ISOROOT

At build time a plain cp -R is enough (nothing pre-exists). Because build.sh (not pkg) placed them, pkg upgrade has no record of them — upgrade-safe, exactly like os-release. The seed.sh only-if-absent variant is reserved for a future package-only install onto an already-populated system. Both the nextbsd img/ISO assembler and nextbsd-userland's minimal CI test image call the same source, so there's one definition.

6. The nextbsd-pkg delta

Almost nothing, by design. The find-based plist (scripts/build.sh:41) just works once the stage stops carrying the stripped /etc and starts carrying the make-installed maintained files. No @config — maintained files are meant to overwrite on upgrade, and the user-editable ones that would have wanted @config are gone to the seed repo entirely. The one real edit: extend the existing base-overlap drop (the rm -f stage/compat/usr/include/Block.h … block) to rm -f any /etc data files kept as maintained (services/protocols/man.conf) so base and userland don't both own the path.

7. Rollout sequence

  1. Create nextbsd-redux/nextbsd-overlays via git filter-repo from nextbsd-userland (history preserved, overlay/ → rootfs/); add iso/ (lifted from build.sh), seed.sh, README/LICENSE/VERSION.
  2. nextbsd-userland PR: (1) add FILESGROUP install rules + move the 6 overlay-only plists into their src/ dirs + new src/system-launchd/ & src/tests/* Makefiles (+ driver lines); (2) delete the seed /etc + dropped files from overlay/; (3) wire nextbsd-overlays into the minimal-image assembly. CI green ⇒ test image still boots.
  3. nextbsd-pkg PR: add the /etc conflict-drops (only if keeping services/… as maintained). Rebuild packages.
  4. nextbsd PR: add the cp -R rootfs/ seed + iso/ consumption to build.sh; fix the three stale overlays/ comments. Rebuild → img-test/iso-test boot (login works ⇒ seed + pwd_mkdb OK).
  5. Order: land the install-rules + seed step before stripping the files from the package, so there's never a window where a seed file is in neither the package nor a seed source.

8. Risks & open flags

  • Doctrine drops (§4) — confirm rc.d/ldconfig, rc.subr, and the services/protocols/man.conf base-duplication calls before building rules for them.
  • Ordering gap — strip only after both assemblers seed, or an image boots with no accounts.
  • Two consumers — nextbsd-userland's minimal CI image (ci/assemble-image.sh, OVERLAY=… at build-arch.yml:141) must pull nextbsd-overlays too, or it boots without the seed.
  • master.passwd mode — git can't store 0600; the seed step re-chmods (as build-arch.yml:114 does today).
  • Package-only install — the img/ISO path is covered; a bare-metal pkg install onto a running system would use seed.sh from a first-boot job (future).
