freebsd-apple-userland-cmds — per-repo, per-binary port audit

A data-grounded audit of six Apple userland repos — bootstrap_cmds, file_cmds, shell_cmds, system_cmds, network_cmds, text_cmds — for the question "should we replace FreeBSD's version with Apple's?". Decision rule: port if Apple's version gives Mach IPC integration, libxpc/libdispatch/launchd integration, or a real feature advantage over the FreeBSD equivalent. Skip if there's no advantage. Tables grounded in direct source inspection by five parallel research agents over /Users/jmaloney/Documents/launchd/{bootstrap,file,shell,system,network,text}_cmds/. Tools install at their Apple-canonical paths with zero conflict: FreeBSD-runtime + FreeBSD-utilities are not installed; the ~40 FreeBSD-specific tools we still need (mount/fsck/kld*/swapon/gpart/… + the audit-skipped POSIX shell tools) are built from /usr/src per-tool via a tracked manifest. See §1.1 for the manifest and §1.2 for the sequencing — the manifest build lands after the daemon-port roadmap (mDNSResponder etc.) to keep CI fast during the high-iteration daemon work.

1. Decisions made

  • Apple-canonical install paths. No /System/Library/Tools/, no /usr/local/sbin/, no PATH-shadowing. Apple's ifconfig goes at /sbin/ifconfig.
  • Drop FreeBSD-runtime + FreeBSD-utilities entirely; build the gap-fillers from /usr/src. Earlier framing («install FreeBSD-runtime intact, then overwrite the ~17 conflict paths») is rejected — it leaves pkg's database believing FreeBSD-runtime owns paths Apple ports actually own, and a stray pkg upgrade on a dev machine silently reverts the overwrites. New approach: pkgbase has no subpackage granularity, so for the ~40 FreeBSD-specific tools we still need (filesystem mount/check, kld*, swap, GEOM, audit-skipped POSIX shell tools) we build each from /usr/src/<dir>/ via a manifest file (pkglist-fbsdsrc-manifest.txt in the freebsd-launchd-mach repo), iterated by build.sh as make obj && make && make install DESTDIR=$WORK/rootfs MK_MAN=no. See §1.1.
  • Sequencing: gap-filler manifest lands after the daemon-port roadmap. Per-tool /usr/src builds increase CI time. The freebsd-launchd-mach daemon ports (configd remaining work, IPConfiguration iter 7+ — RA/SLAAC, DHCPv6 — ipconfig(8), mDNSResponder, notifyd, ASL, DiskArbitration, etc.) iterate heavily; the Apple-userland-cmds work + manifest build move in after those daemons stabilize. Until then, the live ISO uses /rescue/* (already in FreeBSD-rescue) for the minimal early-boot toolset.
  • Port-if-advantage, skip-otherwise. The audits below enforce this strictly. No "port for completeness" entries.
  • Apple-canonical paths land cleanly. With FreeBSD-runtime + FreeBSD-utilities absent, the 28 Apple ports + the manifest-built FreeBSD gap-fillers occupy disjoint paths. pkg's database is authoritative for everything it installs; no unregistered overwrites.

1.1. BSD gap-filler manifest — built from /usr/src per-tool

The 28-binary Apple port list (§9) covers everything where Apple has a real integration advantage. The categories below are FreeBSD-specific tools we still need on the live system — Apple's equivalents either don't exist, target HFS+/APFS only, or use macOS-kernel-specific interfaces that don't translate. With FreeBSD-runtime + FreeBSD-utilities dropped from pkglist-base.txt, these are built per-tool from /usr/src/<dir>/ in the builder chroot and installed into the ISO rootfs.

The list lives in pkglist-fbsdsrc-manifest.txt at the root of the freebsd-launchd-mach repo (created when the workstream starts; see §1.2 sequencing). build.sh iterates each line as (cd /usr/src/$DIR && make obj && make && make install DESTDIR=$WORK/rootfs MK_MAN=no MK_TESTS=no) in the FreeBSD-15 builder chroot. Manifest format: one /usr/src-relative directory per line; # for comments.

Bottom line: ~40 manifest entries replace the role FreeBSD-runtime + FreeBSD-utilities used to play, at the cost of per-tool make-loop time on the builder. The trade is: clean pkg DB, no overwrite-after-install dance, no risk of pkg upgrade silently reverting Apple ports on dev machines. Cost: builder CI time goes up by the cumulative make-loop wall-time of ~40 tiny /usr/src dirs — estimated 2–5 minutes per build. That's why this workstream is sequenced last (§1.2).

1.2. Sequencing — when the manifest build lands

The Apple-userland-cmds port list + the gap-filler manifest are deferred until the high-iteration daemon ports inside freebsd-launchd-mach stabilize. The daemon ports iterate heavily (often 4–6 CI rounds per iter to chase BPF / MIG / SCDynamicStore quirks — see the IPConfiguration progress log for shape); adding 2–5 minutes per CI run on top of that is unnecessary drag.

Order of operations:

  1. Finish the daemon roadmap. Configd remaining iters, IPConfiguration iter 7 (RA/SLAAC) + iter 7b (DHCPv6) + iter 8 (ipconfig(8) CLI), mDNSResponder port, notifyd, ASL, DiskArbitration, any other Phase K daemon work.
  2. Bootstrap MIG. Build + install Apple's mig + migcom from bootstrap_cmds (zero conflict — pure addition; no /usr/src dependency).
  3. Drop FreeBSD-runtime + FreeBSD-utilities from pkglist-base.txt. One PR. Boot will break until step 4 lands; that's expected.
  4. Land pkglist-fbsdsrc-manifest.txt + the build.sh iteration step. Same PR or immediate follow-up. Boot test green at the end of this step.
  5. Then iterate through the 28-binary Apple port list per §9, in the order in §10. Each binary either compiles + tests clean at its canonical path or doesn't — no overwrite dance.

Until step 3, the existing approach stays: FreeBSD-runtime + FreeBSD-utilities installed via pkgbase. Apple's ipconfig(8) in IPConfiguration iter 8 installs at /usr/sbin/ipconfig (no conflict — FreeBSD has no such tool), so the IPConfiguration story closes before this workstream begins.

10. Install order in build.sh

Order assumes the §1.2 sequencing precondition: all freebsd-launchd-mach daemon ports (configd, IPConfiguration through iter 8, mDNSResponder, notifyd, ASL, DiskArbitration, …) have already shipped.

  1. pkg install the trimmed pkgbase set (pkglist-base.txt with FreeBSD-runtime + FreeBSD-utilities removed; FreeBSD-clibs, FreeBSD-rescue, FreeBSD-ufs, FreeBSD-geom, FreeBSD-pam*, … remain).
  2. Build the BSD gap-fillers from /usr/src per pkglist-fbsdsrc-manifest.txt (§1.1). For each line, (cd /usr/src/$DIR && make obj && make && make install DESTDIR=$WORK/rootfs MK_MAN=no MK_TESTS=no). Marker: FBSDSRC-MANIFEST-OK on a clean iteration. Boot test green at this point with just BSD + the daemon stack — no Apple userland-cmds yet.
  3. Build bootstrap_cmds; install mig + migcom. Marker: MIG-BUILD-OK. (Note: mig bootstrap can actually move earlier if a daemon port needs it — it's pure addition, no FreeBSD conflict.)
  4. Run mig against the seven launchd-842 .defs files; cache output in src/launchd/mig-output/.
  5. Build + install network_cmds tools (10 binaries). One smoke marker per tool: NETCMD-IFCONFIG-OK, NETCMD-PING-OK, NETCMD-ROUTE-OK, …
  6. Build + install file_cmds tools (7 binaries). Markers: FILECMD-CP-OK, …
  7. Build + install shell_cmds tools (id, su). Ship a no-op libopendirectory shim so id falls back to /etc/passwd.
  8. Build + install system_cmds tools that don't need new kernel traps yet. Defer lsmp / hostinfo / stackshot until the mach.ko-side traps land.
  9. Build + install sort from text_cmds. Last because it adds Mach-semaphore use to a generic stream tool — isolation matters.

11. Risks & known sharp edges

ABI drift between Apple and FreeBSD kernel structs

Worst in ifconfig, netstat, route, arp, ndp. Apple extends struct ifreq, struct ifmediareq, struct rt_msghdr; some Apple ioctls don't exist on FreeBSD. Apple-only feature paths will fail gracefully (ioctl returns -1, flag never set) — acceptable.

Open Directory dependency for id

Apple's id calls libopendirectory. FreeBSD has no equivalent. Ship a no-op shim; id falls back to /etc/passwd like FreeBSD's. Real OD work is a separate, far-future phase.

Mach traps needed before system_cmds Tier B

4 new traps for lsmp + hostinfo + stackshot (port-space introspection, host info flavors, stackshot syscall). All fit the multiplexer slot 219 pattern; ~600 LOC of mach.ko work. nvram needs an IOKit NVRAM driver — separate track, much bigger.

CI time impact of the /usr/src manifest build

~40 per-tool make obj && make && make install loops add an estimated 2–5 minutes per build — non-trivial when the daemon ports iterate 4–6 CI rounds per iter. Mitigation is sequencing, not optimization: this workstream lands only after the daemon roadmap stabilizes (§1.2). Once landed, build cache + parallel make can claw some of it back if needed.

/usr/src availability on the builder

The manifest assumes a full /usr/src tree of the matching FreeBSD release on the builder chroot. Today the builder already has this (used for kmod compiles); the manifest just adds new directories to it. If the builder ever moves to a src-less chroot, the manifest workstream needs a paired src.txz fetch step or a switch to a single buildworld-style invocation.

cp --reflink semantics

Apple cp uses clonefile(2) automatically on supported filesystems. On FreeBSD UFS this no-ops to byte-copy. On ZFS we might want it to call zfs_clone_range eventually; not required.

libdispatch dependency for mtree + sort

Both use libdispatch. We already ship /usr/lib/system/libdispatch.so, so this is free.

12. Out of scope

  • FreeBSD-rc removal. Once launchd-842 is PID 1, its plists own multi-user bring-up. Drop the pkg then. Gershwin Phase 2 reference.
  • /sbin/init replacement. Overwrite with launchd-842 binary or symlink. Same overwrite-after-install model.
  • IOKit NVRAM driver. Real EFI device-tree walker for nvram; separate kernel-side track.
  • Open Directory framework. Real enterprise-directory backend for id, login, auth. Months of work.
