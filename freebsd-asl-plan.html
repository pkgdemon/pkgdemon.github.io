FreeBSD ASL — porting plan

A FreeBSD-only port of Apple's ASL (Apple System Logger) — Apple's pre-unified-logging structured logging framework — replacing BSD syslog as the primary log infrastructure once we want richer-than-text-line records. Drops Mach IPC; replaces with GNUstep Distributed Objects. Companion to freebsd-launchd, freebsd-configd, and freebsd-kmodloader.

Status: planning v0 — deferred

  • Repo: github.com/pkgdemon/freebsd-launchd — monorepo. ASL source under asl/ at the top, alongside src/ (launchd), configd/, kmodloader/. Single build pipeline, single CI, single boot test.
  • Mission: ship a structured-record logging system on FreeBSD modeled on the API the rest of the Apple-derived userland already speaks (asl_log()). Apps that have used asl(3) on macOS port without API changes; queries via the syslog(1) CLI work. BSD syslogd stays operational for backward compat — the ASL syslogd is rewritten Apple-side to ALSO write BSD-format /var/log/messages via bsd_out.c, so existing FreeBSD tools keep working.
  • Why this is deferred: the launchd port works fine with plain BSD syslog (already shipped at commit 9f6c479). ASL is an upgrade path — it gives us structured query (filter by Sender, Facility, PID, Time-range without grep tricks), per-job log filtering for launchctl logs <label>-style features, and matches the API expected by application code we'd inherit from macOS. Phase 6+ work, well after configd and kmodloader.
  • Source: Apple syslog-97.1 (latest tag at apple-oss-distributions/syslog, APSL 2.0). 47 source files, ~38k LOC. 12 files have <mach/> includes; one MIG .defs file (aslcommon/asl_ipc.defs). Phase 1 amputation drops the Mach plumbing.
  • No Mach IPC. The asl client library (libsystem_asl) talks to the syslogd database server via Mach in Apple's source. Replaced with GNUstep Distributed Objects (NSConnection + NSPortCoder) over AF_UNIX, same pattern as the configd port.
  • Event loop: libdispatch dispatch sources only (kqueue under the hood). DISPATCH_SOURCE_TYPE_READ on /dev/klog for kernel-log ingestion; on /var/run/log Unix socket for BSD-syslog wire-format clients; on the DO socket for ASL clients. DISPATCH_SOURCE_TYPE_VNODE on /etc/asl.conf for live config reload.
  • Coexistence with FreeBSD's syslogd: the Apple ASL syslogd implements the BSD-syslog wire protocol natively (bsd_out.c writes /var/log/messages et al. with the conventional facility/level routing). After this port lands, FreeBSD's stock syslogd is uninstalled; the ASL syslogd takes over both roles. Existing programs that call syslog(3) see no API change.
  • Licensing: Apple's source is APSL 2.0 (not Apache 2.0 like launchd/configd). FSF-approved free software license; per-file headers preserved on Apple-derived files; our top-level repo stays BSD-2-Clause; same inbound=outbound rule as the other ports.

1. Goal & non-goals

1.1 Goal

Replace FreeBSD's /usr/sbin/syslogd with a port of Apple's ASL-backed syslogd, providing: (a) the BSD-syslog Unix-socket protocol so existing programs calling syslog(3) Just Work; (b) the asl(3) C API for richer structured logging by Apple-derived userland; (c) a syslog(1) CLI for queries that filter on structured fields (Sender, Facility, PID, Time, custom keys) without resorting to grep; (d) a binary store under /var/log/asl/*.asl for fast indexed queries; (e) text fallback in /var/log/messages for tooling that walks log files directly. Eliminates the gap between "what FreeBSD ships" (text-line BSD syslog) and "what the Apple-shaped userland expects" (structured ASL records).

1.2 Non-goals (this iteration)

  • No unified logging (os_log). Apple's modern post-ASL system (macOS 10.12+) is a much bigger project — the logd daemon and tracev3 binary format aren't fully open-sourced. ASL is the largest open-source Apple logging system that's portable. Out of scope.
  • No Mach IPC. Same project-wide rule. asl_ipc.defs (the MIG IDL between client and server) is deleted; replaced with DO.
  • No iOS/iPadOS plist variants. Files like asl.conf.ios, asl.conf.ios_sim, com.apple.syslogd_sim.plist are dropped.
  • No SecurityFoundation log redaction. Apple's syslogd integrates with the SecurityFoundation framework for privacy markers ({public}, {private} in os_log format strings). ASL's redaction is simpler; we keep what's already there but don't add new privacy plumbing.
  • No aslmanager rotation policy reimagining. Apple's aslmanager.tproj rotates the .asl store. We port it as-is; FreeBSD already has its own newsyslog for /var/log/messages-style files.
  • No backwards port to launchd's pre-Phase-3a stage. ASL needs Foundation + libdispatch (linked into syslogd). The system domain has to be in place; this work depends on launchd Phase 2 having shipped.

3. Architecture

+---------------------+ | /etc/asl.conf | +-----------+---------+ | (vnode source: live reload) v +---------------------+ +-----+------+ +-------------------------+ | /dev/klog |-->| syslogd |<--| /var/run/netconfigd.sock| | (kernel ringbuf; | | (ObjC, | | wait — wrong sock; the | | READ source) | | GNUstep, | | ASL one is below) | +---------------------+ | Apple | +-------------------------+ | source) | +---------------------+ | | +-------------------------+ | /var/run/log |-->| |<--| /var/run/asl_input | | (BSD syslog Unix | | | | (DO connection for ASL | | socket; READ src) | | | | clients via NSConnect.)| +---------------------+ +-----+-----+ +-------------------------+ | | (writes go to BOTH stores) v +-----------------+-----------------+ | | v v +--------+--------+ +-------+--------+ | /var/log/asl/ | | /var/log/ | | *.asl | | messages, | | (binary store, | | auth.log, | | daily-rotated | | maillog ... | | by aslmanager) | | (BSD text; | +-----------------+ | newsyslog | | rotates) | +----------------+

3.1 The two stores, one daemon

This is the load-bearing design choice that makes ASL palatable for FreeBSD: the syslogd daemon writes both a binary ASL store (queryable via syslog(1) with structured filters) and the conventional BSD-syslog text files (/var/log/messages, /var/log/auth.log, etc., readable with tail / grep / any tool that walks files). Apple's bsd_out.c implements this — the source of asl.conf's "rule"-based output routing is already split between an asl_db backend and a bsd-text backend.

Existing FreeBSD admin habits (read /var/log/messages, run logger from a script) keep working unchanged. New apps that want structured queries get them. No tradeoff on the user side.

3.2 Replacing Mach IPC with DO

The asl client library (libsystem_asl) buffers messages and ships them to syslogd via a Mach-IPC dance defined in aslcommon/asl_ipc.defs. We replace this with:

  • Server side: syslogd creates an NSConnection over a known AF_UNIX socket (/var/run/asl_input) at startup. Implements an @protocol ASLInput with a -submitMessage: method.
  • Client side: libsystem_asl.tproj's wire-format functions are replaced with NSConnection rootProxy + a remote message send. Marshalling via NSPortCoder (which handles dictionary-of-strings-of-ints natively, exactly what asl messages are).

For BSD-syslog clients (syslog(3)), no change — the same Unix datagram socket at /var/run/log stays open, daemon parses BSD wire format on it as before.

8. launchd integration

8.1 The plist (replaces our current minimal one)

Today (Phase 3), org.freebsd.syslogd.plist in the freebsd-launchd overlay invokes FreeBSD's /usr/sbin/syslogd -F -ss. After this port lands, the same plist invokes the ASL-backed syslogd at the same path. The plist gains a Sockets key for the DO connection:

<?xml version="1.0" encoding="UTF-8"?>
<plist version="1.0">
<dict>
    <key>Label</key>            <string>org.freebsd.syslogd</string>
    <key>ProgramArguments</key> <array><string>/usr/sbin/syslogd</string></array>
    <key>RunAtLoad</key>        <true/>
    <key>KeepAlive</key>        <true/>
    <key>Sockets</key>          <dict>
        <key>ASLClients</key>
        <dict>
            <key>SockPathName</key> <string>/var/run/asl_input</string>
            <key>SockType</key>     <string>stream</string>
            <key>SockPathMode</key> <integer>438</integer> <!-- 0666 -->
        </dict>
        <key>BSDClients</key>
        <dict>
            <key>SockPathName</key> <string>/var/run/log</string>
            <key>SockType</key>     <string>dgram</string>
            <key>SockPathMode</key> <integer>438</integer>
        </dict>
    </dict>
</dict>
</plist>

launchd opens both sockets and hands fds to syslogd via launch_activate_socket. Connection queue stays warm even if syslogd is restarting.

9. CLI tool — syslog(1)

Apple's syslog command is the query interface. Phase 3 ports it. Subset of commands:

  • syslog — dump recent messages (last hour by default)
  • syslog -w — live stream new messages
  • syslog -k Sender launchd — filter by structured key
  • syslog -k Time ge -1h — time-range filter
  • syslog -F xml — output structured records (the proof-of-concept query)
  • syslog -c <sender> <level> — set per-sender filter level

This is what FreeBSD admins already do with tail /var/log/messages | grep ..., just made declarative. Both work after this port lands.

10. Licensing

Apple's syslog source is APSL 2.0 — Apple Public Source License Version 2.0. Different from launchd / configd (which are Apache 2.0). APSL is FSF-approved as a free software license; not GPL-compatible (so we couldn't combine APSL files with GPL-licensed code in a single binary, but our project doesn't use any GPL — just LGPL/MIT/Apache for system-domain libs, all compatible).

11. Phased delivery

Phase 0 — repo scaffold + import

  • Create asl/ at the top of freebsd-launchd. Update NOTICE for APSL 2.0 attribution.
  • Add asl/scripts/import-source.sh that clones apple-oss-distributions/syslog at syslog-97.1, strips .git, drops it under asl/src/.
  • One-shot import commit (verbatim Apple tree).
  • Follow-up amputation commit per §6.1 (Mach + Xcode + iOS-sim + sandbox out).
  • No build wired up; ISO unchanged.

Phase 1 — minimal asl-backed syslogd, BSD-text-only output

  • Top-level asl/Makefile + make-asl.sh.
  • Port syslogd.tproj/syslogd.c, daemon.c, klog_in.c, bsd_out.c: minimum daemon that reads /dev/klog + /var/run/log and writes /var/log/messages. ASL store + DO not yet wired up.
  • Replaces FreeBSD's /usr/sbin/syslogd in the ISO. Existing syslog(3) calls continue to work; nothing user-visible changes.
  • Boot test extension: confirm /var/log/messages is being written (file size grows post-boot).

Phase 2 — ASL binary store + asl(3) library

  • Port aslcommon/, libsystem_asl.tproj/src/asl.c, syslogd.tproj/dbserver.c.
  • Wire up the DO connection at /var/run/asl_input; libsystem_asl's submit path uses NSConnection.
  • Daily-rotated .asl files start populating /var/log/asl/.
  • Boot test: confirm an ASL store file exists post-boot.

Phase 3 — syslog(1) CLI tool

  • Port util.tproj/syslog.c. Replaces Mach store-query client with DO query client.
  • Boot test extension: ssh in, run syslog -k Sender launchd, verify output includes "starting (pid=1 ...)".

Phase 4 — aslmanager rotation

  • Port aslmanager.tproj/aslmanager.c. Wire up via launchd plist org.freebsd.aslmanager.plist (StartCalendarInterval, daily).
  • asl.conf rule evaluation (asl_action.c) finalized.
  • UDP/remote inputs (udp_in.c, remote.c) wired up if needed for off-box logging.

Phase 5+ — optional, demand-driven

  • launchd's own log routing migrated from stderr-to-file (the Phase 3d crutch we added to init.sh) to asl_log() calls. Removes the boot-time stderr→file redirection.
  • Per-job query for launchctl logs <label> — uses syslog -k Sender <label> internally.
  • Live filter API for tools that subscribe to specific keys via DO (matching configd's dynamic-store fan-out pattern).

12. Open questions

Q1. Coexistence with FreeBSD syslogd during transition. Phase 1 replaces base.txz's /usr/sbin/syslogd. Is that safe for partial deployments? Decision: yes — the replacement implements the BSD-syslog wire protocol natively (bsd_out.c), so anything that called syslog(3) sees no API change. In the ISO build, the overlay clobbers the base binary; in installed-system territory, the user opts in via package install.
Q2. APSL vs Apache mixing. Open. Both are FSF-approved free software licenses, both are GPL-incompatible. In the same monorepo with launchd/configd files (Apache) and asl files (APSL), both per-file licenses are preserved. The combined work distributes as BSD-2-Clause at top-level + per-file Apache OR APSL on Apple-derived files. No friction expected. Verify with one round of legal review when this ships if there's enterprise concern.
Q3. asl.conf format compatibility. Apple's asl.conf shipped with macOS uses Apple-specific routing rules (e.g., to the unified-logging bridge). Our port ships a simpler asl.conf matching FreeBSD-style facility/priority routing. Decision: ship a curated asl.conf in the overlay that mirrors FreeBSD's /etc/syslog.conf defaults plus an asl-store catch-all rule.
Q4. Sandbox profile (syslogd.sb). Apple sandboxes syslogd via sandbox(7) on macOS. FreeBSD has Capsicum but the policies don't translate directly. Decision: drop the Apple sandbox profile; revisit Capsicum-based sandboxing as a Phase 6 hardening pass.
Q5. syslog CLI vs FreeBSD logger(1) overlap. FreeBSD's logger(1) writes via syslog(3); our port keeps that working. Apple's syslog CLI is read-mostly (queries) plus -s for sending. The two coexist fine at separate paths (/usr/bin/logger, /usr/bin/syslog); users pick by intent.
Q6. Migration story for already-deployed FreeBSD systems. If a user installs freebsd-asl on a running FreeBSD server with active log files, what happens to /var/log/messages? Decision: nothing — bsd_out.c writes to the same file in the same format. No migration needed. ASL's binary store under /var/log/asl/ starts populating fresh.
