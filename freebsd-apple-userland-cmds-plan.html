freebsd-apple-userland-cmds — bootstrap_cmds + network_cmds

Porting Apple's bootstrap_cmds (ships MIG; needed before launchd-842 can use its .defs stubs) and network_cmds (Apple's network userland: arp, ifconfig, ndp, netstat, ping, route, etc.) onto FreeBSD. Tools install at their Apple-canonical paths; we overwrite FreeBSD-runtime's binaries where they conflict and accept CI breakage during the transition rather than build an alternate-prefix shadow stack we'd have to unwind later. A companion to the launchd-842 port plan.

1. Decisions made

  • Apple-canonical install paths. No /System/Library/Tools/, no /usr/local/sbin/, no PATH-shadowing scheme. ifconfig goes at /sbin/ifconfig, full stop. The Apple tools are the production tools.
  • FreeBSD-runtime stays installed for now. It carries /sbin/init, /sbin/halt, /sbin/reboot, mount — bits we still need until launchd-842 is PID 1 (Phase I3+) and Apple's system_cmds lands (Tier B, much later). pkgbase doesn't expose subpackage granularity, so we install FreeBSD-runtime intact and then overwrite the conflict paths with our binaries.
  • Accept CI breakage during transition. We're not building a stable shadow stack. Each port either works at its canonical path or doesn't. Breakage is fixed in-place rather than worked around. The 20-marker safety net comes back online once each component lands — same iterate-on-red model we used during Phase H libxpc.
  • No spike doc, no preemptive conflict matrix. The replacement table below is the spike. pkg info -l FreeBSD-runtime on bsd01 will confirm exact path ownership if needed later; we don't need it before starting.
  • Unregistered overwrites are fine. pkg's database still believes FreeBSD-runtime owns /sbin/ifconfig. Subsequent pkg upgrade FreeBSD-runtime would silently restore the FreeBSD version. We don't pkg upgrade on the live ISO; this only matters on dev machines and is documented as a known sharp edge.

Build approach

  • migcom is yacc/lex/C; FreeBSD has byacc + lex in base. Should compile with stock cc + minimal Apple-shim headers.
  • mig itself is the shell wrapper mig.sh — installed as /usr/bin/mig, invokes /usr/libexec/migcom.
  • Once installed, generate the seven .defs files from launchd-842 into a vendored mig-output/ directory so launchd-842 builds don't require regenerating per CI run.

Counts: 11 conflicts with FreeBSD-runtime; 4 clean adds (already-omitted pkgs or Apple-only).

Build approach

  • Each .tproj dir builds independently; cc + small Apple-shim header set (<TargetConditionals.h>, etc., reused from libxpc shims).
  • ifconfig is the riskiest port: it talks to kernel via SIOCG*/SIOCS* ioctls, and Apple's struct definitions diverge from FreeBSD's in places. Expect per-ifconfig-subcommand patches.
  • ping, route, traceroute are mostly self-contained — raw sockets + routing-socket parsing. Most likely to land cleanly.
  • netstat reads kernel structures via sysctl(net.*) — another candidate for divergence between Apple and FreeBSD struct shapes.
  • Per-tool smoke markers: NETCMD-IFCONFIG-OK (just ifconfig -l succeeds), NETCMD-PING-OK (loopback ping returns), etc. One marker per tool keeps blast radius narrow.

4. Install order in build.sh

Linear sequence inside the existing build pipeline (additive after the libxpc stage):

  1. pkg install FreeBSD-runtime (already done in the pkgbase stage).
  2. Build bootstrap_cmds; install mig + migcom. Verify mig --help exits 0 in chroot.
  3. Run mig against launchd-842/src/*.defs; cache generated output under src/launchd/mig-output/.
  4. Build network_cmds tool-by-tool; install each at the path in the table above. Each cp overwrites the FreeBSD-runtime-owned file.
  5. Run each tool's smoke marker; advance to the next.

The overwrite step is intentionally not registered with pkg. No pkg create, no pkg add, no replacement pkg manifest. The binaries simply sit on the rootfs at their canonical paths. pkg check will flag them as modified; we accept that.

If a future iteration wants properly-registered ownership, the right path is to build a slim FreeBSD-apple-network-shaped pkg that CONFLICTS= with the affected subset of FreeBSD-runtime — but that requires either rolling our own pkgbase manifest or vendoring a custom FreeBSD-runtime minus the network bits. Both are out of scope here.

5. Risks & known sharp edges

ABI drift between Apple and FreeBSD kernel structs

ifconfig and netstat reach into kernel-defined structs (struct ifreq, struct ifmediareq, struct rt_msghdr, the net.inet.* sysctl namespaces). Apple has extended several of these (e.g., SIOCSIFLLADDR internals, multicast routing extras). Per-tool patching is expected. Some Apple-only features will simply be unavailable on FreeBSD — we accept it.

pkg upgrade restores FreeBSD versions

Any pkg upgrade FreeBSD-runtime silently puts the FreeBSD binaries back. The live ISO never pkg upgrades; dev machines should add the affected paths to a "do not touch" list or simply re-run the overwrite step after upgrades.

Symlinks: ping6

FreeBSD ships /sbin/ping6 as a symlink to /sbin/ping. Apple's network_cmds ships them as two independent binaries. We replace the symlink with a real binary. ping with no -6 flag should still default to IPv4 either way; minor behavioral difference.

rtsol vs rtsold

FreeBSD names it rtsold (daemon). Apple names the daemon variant rtsol and the controller rtsold. We pick Apple's naming and let rtsold stop being a file the ISO ships. Cosmetic; no daemon-supervision impact.

SystemConfiguration coupling

Apple's network_cmds tools occasionally call into SystemConfiguration.framework for store reads/writes (DNS notifications, link-state changes). FreeBSD has no SC framework yet. Stub those code paths out per-tool; reactivate when configd lands.

6. Out of scope (deferred to Phase I3+ or later)

  • FreeBSD-rc removal. Once launchd-842 is PID 1 and its plists own multi-user bring-up, the /etc/rc* shell scripts become dead weight. Drop the pkg then. Gershwin Phase 2 is the reference for how this works in practice.
  • /sbin/init replacement. Cannot drop FreeBSD-runtime, but can overwrite /sbin/init with launchd-842 (or a symlink to it). Same overwrite-after-install model as the network tools.
  • system_cmds port (halt, reboot, shutdown, mount, ps, kill, ...). Tier B in the launchd-842 plan. Its own dedicated phase, after Phase I3.
  • shell_cmds + file_cmds. Tier B continuation. Replaces the rest of FreeBSD-runtime's userland; lets us aggressively slim the runtime pkg footprint.
  • Custom pkgbase manifest that excludes the overwritten paths. Nice-to-have. Doesn't block any port.
